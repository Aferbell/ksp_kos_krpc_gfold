## 1. 水平具体是怎么控制的

### 1.1 三件事拼在一起

```
水平加速度指令  a_h_vec  =  u_r_h     +  kv*dve  +  kp*dp
                            ↑             ↑          ↑
                        规划前赡点    速度误差   位置误差
                       （前馈）      （阻尼）    （刚度）
```

代码 `starship_land.py:1360-1361`：

```python
_ah_vec = (np.asarray(u_r, float)[1:3].copy()
           + _ca_kv * _dve + _ca_kp * _dp)
```

| 项 | 含义 | 作用 |
|---|---|---|
| **`u_r_h`（前馈）** | 规划在前赡点 `n_look` 处的水平推力分量 | 规划说「该往哪推、推多少」 |
| **`kv*dve`（阻尼）** | `dve = v_r - v`，前赡点速度与当前速度之差 | 抑制「冲过头」 |
| **`kp*dp`（刚度）** | `dp = x_r - x`，前赡点位置与当前位置之差 | 拉回目标 |

### 1.2 「eguidance」体现在哪

```python
_ca_T = 2.0 * _perr / max(0.05, _verr)      # 自适应时标
_ca_T = max(T_GAIN_MIN, min(T_GAIN_MAX, _ca_T))
_ca_kv = 4.0 / _ca_T
_ca_kp = 6.0 / (_ca_T * _ca_T)
if TILT_GAIN_CAP_ENABLE:
    _ca_kv = min(TILT_GAIN_MAX, _ca_kv)
```

**这是 E-Guidance 的核心**：时标 `T = 2·|误差| / |误差变化率|`，
然后 `kv = 4/T`、`kp = 6/T²`，这样 `zeta = 4/(2·sqrt(6)) = 0.816` 恒定。

### 1.3 ⚠️ 但自适应【完全失效了】

```
T_GAIN_MIN = 8.0
T_GAIN_MAX = 8.0        <- 上下限相同！
```

**实测这两趟 `ca_T` 全程恒为 8.00**，`T = 2·perr/verr` 被夹死。
于是增益退化成固定值：

```
kv = 4/8  = 0.500
kp = 6/64 = 0.09375
```

**这是第一个可以拨的旋钮，而且它本来就是为「调快调慢」设计的。**

### 1.4 从 a_h 到倾角

```
tilt_cmd = atan2(a_h, a_up)          # a_up 竖直加速度 ≈13.8 m/s²
tilt_cmd = clamp(tilt_cmd, 0, tilt_allow)
```

`tilt_allow` 由高度决定：

```
tcap = clamp(alt / TILT_CAP_SLOPE, TILT_CAP_LO, TILT_CAP_HI)
     = clamp(alt / 10, 5.0, 35.0)
```

| alt | `tcap` | a_h 上限（`a_up=13.8`）|
|---|---|---|
| 900 | 35.0° | 9.66 m/s² |
| 300 | 30.0° | 7.97 |
| 200 | 20.0° | 5.02 |
| 120 | 12.0° | 2.93 |
| 50 | 5.0° | 1.21 |

### 1.5 四道限制（按施加顺序）

| # | 限制 | 代码行 | 作用对象 |
|---|---|---|---|
| ① | **能力夹限** `ah_sat` | `:1497` | 需求 `ah_dem` → `min(ah_dem, a_up·tan(tilt_allow))` |
| ② | **jerk 限幅** | `:1521-1537` | 相邻帧 `a_h` 变化率 → `j_max·dt` |

| ④ | **参考方向速率限制** | `_limit_ref_slew` | 三维姿态参考角速率 → `sqrt(2·alpha·45°)` |

## 4. 代码里的限制有没有起作用

| 限制 | 131055 | 132426 | 判定 |
|---|---|---|---|
| `ah_sat`（需求 > 能力） | **14%** | **68%** | 132426 **高度绑定** |
| `ah_cap_bind`（jerk 后仍超能力） | 0% | 0% | 未绑定 |
| `j_used/j_max >= 0.95` | **8%** | **3%** | **基本没起作用** |
| `ref_slew` 贴 20 上限 | **13%** | 8% | **基本没起作用** |
| `tilt_cmd_rate` p50 / max | 7.5 / **30.1** deg/s | 5.5 / **49.1** deg/s | **远超 20 的 ref 上限** |

### 4.1 为什么限制没拦住

```
jerk 限幅：j_used/j_max p50 只有 0.35 / 0.01，远没到限
ref_slew ：p50 只有 10.8 / 2.7 deg/s，远低于 20
但 tilt_cmd_rate 峰值 30.1 / 49.1 deg/s —— 已超物理能力
```

**原因**：`tilt_cmd_rate` 是「`ah_dem` → `tilt_cmd`」的原始需求速率，
而 `ref_slew` 限的是「三维参考方向」的速率。两者不是一回事：

```
ah_dem 可在 1 帧内从 6.5 掉到 2.5（前赡点 u_r 跳变）
  => tilt_cmd 从 23.7 掉到 10.2（1 帧）
  => 但 ref_slew 限的是三维方向，小倾角时 sin(tilt) 很小
  => 三维代价 = sin(tilt)*d_az ≈ 0  => 完全放行
```

**这就是老问题：小倾角时倾角/方位的小变化在三维上「免费」，限制器看不见。**

## 5. 你的想法：「让载具响应慢一点」

### 5.1 方向是对的，但要分清「慢」是哪个慢

| 慢在哪 | 效果 | 代价 |
|---|---|---|
| **增大 `T`（闭环时标）** | 指令变柔和，倾角变小 | 收敛变慢，可能跟不上规划 |
| **降低 `TILT_CAP_HI`** | 峰值直接削掉 | 水平权限下降 |
| 降低 `TILT_CAP_SLOPE` | 低空权限下降 | 低空消不掉横速 |
| 降低 `REF_SLEW_MAX` | 参考方向更慢 | **对倾角几乎无效**（见 4.1）|

### 5.2 增大 `T` 的实测收益

用日志反解 `u_r`，再按不同 `T` 重组 `ah_dem`：

**131055：**

| `T` | `ah_dem` p50 / max | **倾角峰值** | **倾角 p50** |
|---|---|---|---|
| **8（现在）** | 2.09 / 8.84 | **25.23°** | **8.40°** |
| 10 | 1.71 / 6.87 | 22.79° | 6.86° |
| 12 | 1.45 / 5.61 | 21.28° | 5.88° |
| 14 | — | 20.13° | 5.11° |
| 16 | 1.11 / 4.82 | 19.23° | 4.51° |
| 20 | 0.90 / 4.46 | **17.92°** | **3.72°** |

**132426：**

| `T` | **倾角峰值** | **倾角 p50** |
|---|---|---|
| **8（现在）** | **26.51°** | **7.14°** |
| 12 | 17.67° | 5.34° |
| 16 | 13.65° | 4.23° |
| 20 | **12.53°** | **3.49°** |

**⇒ `T` 从 8 到 20（周期 2.5 倍），峰值只降 29%（131055）/ 53%（132426）。**
**p50 降 56% / 51%。** 不是线性的。

### 5.3 为什么非线性

```
ah_dem = |u_r_h + kv*dve + kp*dp|
           ↑        ↑         ↑
        不随 T 变   ∝1/T     ∝1/T²
```

**当 `u_r` 主导时（`T` 大时恰好如此），再增大 `T` 也没用。**
实测 `|u_r|` 峰值 3.42（131055）/ 1.97（132426），而 `T=20` 时反馈项只剩 0.90 / 1.54。

## 6. 更有效的组合

### 6.1 `T` + `TILT_CAP_HI` 一起动

| `T` | `TILT_CAP_HI` | 131055 倾角峰值 | p50 |
|---|---|---|---|
| 8（现在） | 35（现在） | **25.23°** | 8.40° |
| 8 | 25 | 25.00° | 8.40° |
| **8** | **20** | **20.00°** | 8.40° |
| **12** | **20** | **20.00°** | 5.88° |
| 12 | 35 | 21.28° | 5.88° |
| 16 | 35 | 19.23° | 4.51° |

**⇒ `T=12` + `HI=20` 把峰值从 25.2° 压到 20.0°，p50 从 8.4° 压到 5.9°。**

### 6.2 建议（按性价比）

| 优先级 | 改动 | 预期 | 风险 |
|---|---|---|---|
| **1** | **`T_GAIN_MIN = T_GAIN_MAX = 12`** | 倾角 p50 −30%，峰值 −16% | 低（只是变柔和）|
| **2** | **`TILT_CAP_HI` 35 → 25** | 峰值硬削到 25° | 中（水平权限降 28%）|
| 3 | `TILT_CAP_SLOPE` 10 → 15 | 低空权限再降 | 中（低空消横速能力降）|
| 4 | `REF_SLEW_MAX` 20 → 12 | **基本无效**（见 4.1）| 无 |

**建议先只改第 1 项**，单变量，实飞验证「倾角变小了，落点没变差」。

### 6.3 ⚠️ 风险

`T` 增大会让闭环**更慢**，而前赡已补偿 1.5 s 机身滞后。
若 `T` 太大（>16），可能出现「指令还在慢慢转，载具已经飞过目标」。

**验证判据：**

| 列 | 期望 | 不达标说明 |
|---|---|---|
| `tilt_cmd` max | 从 23~30 降到 **<20** | 没生效 |
| `att_err` p50 | 从 9.4~9.7 降到 **<7** | T 太大，追不上 |
| `dist` max | **不比现在差**（25.9 / 36.4 m）| T 太大，收敛变慢 |
| 落地 `dist` | **不比现在差**（8.37 m / timeout）| 两者失衡 |

## 7. `jerk` 限幅为什么没拦住

```python
_sec2  = 1 + (ah_want/a_up)^2
_j_phys = a_up * _sec2 * sqrt(2*alpha*45deg)
_j_lim  = _j_phys * JERK_SLEW_FRAC(0.5)
_j_max  = max(JERK_GUARD_MIN(0.8), min(JERK_GUARD_MAX(60), _j_phys, _j_lim))
```

实测 `j_max` p50 ≈ 4.7 m/s³，`j_used` p50 只有 **0.35 m/s³**。

**它限的是 `a_h` 的变化率，但 `tilt_cmd = atan2(a_h, a_up)`，**
**当 `a_up` 也变时，`tilt_cmd` 的跳变可以远大于 `a_h` 的跳变。**

这两趟 `a_up` 在 13.7~13.9 之间很稳，所以主因不是这个。
**主因是 `ah_dem` 本身在跳**（前赡点 `u_r` 随 `n_i` 变化），
而限幅作用在 `ah_cmd`（输出）上，管不到 `ah_dem`（需求）的跳变。

## 8. 一句话总结

```
1. 水平律 = 前馈 u_r(规划) + kv*dve(阻尼) + kp*dp(刚度)，kv=4/T, kp=6/T²
2. 但 T_GAIN_MIN = T_GAIN_MAX = 8  =>  自适应失效，退化成固定增益
3. 四道限制里只有 ah_sat 真的绑定（14% / 68%），jerk 与 ref_slew 都没起作用
4. 起振根因：姿态滞后 1.33~1.43 s，而指令在 1~2 s 内翻倍 => 欠阻尼
5. T 8->12 能让倾角 p50 降 30%，峰值降 16%（非线性，前馈项不随 T 变）
6. 想更狠就同时降 TILT_CAP_HI 35->25（峰值硬削到 25 度）
```
