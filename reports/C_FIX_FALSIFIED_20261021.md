## 2. 根因认知（这是最有价值的一条）

**180 度翻转不是 bug，是载具「飞过目标后转回来」的唯一途径。**

原逻辑：方位角每帧无条件跟随 `_ah_vec`。当载具穿过目标时：

```
dp 反向  ->  _ah_vec 方向翻转  ->  方位角跳 180 度
=> 载具掉头，飞回来
```

**这正是它该做的事。** 冻住方位角 = 让载具永远朝错误方向飞。

我把它当成「抖动」去抑制，但实际上是**唯一的纠错机制**。

## 3. 方法论教训（比技术结论更重要）

### 3.1 离线回放算不出「载具会飞到哪」

我的回放脚本是这样的：

```python
if ahd > 1e-9 and perr > thr:
    cand = (az_n, az_e)          # 用日志里记录的 _ah_vec 方向
    if 夹角(tf_az, cand) <= 60:
        tf_az = cand             # 采用
    else:
        pass                     # 保持
```

**致命缺陷**：它用**日志里已经飞出来的** `tf_az_n/tf_az_e` 当输入。
这些值来自「原逻辑」的飞行轨迹。一旦方位角被冻结，
**载具实际会飞到哪、`dp` 会变成什么，回放根本不知道**。

所以回放能算出「参考系方位转了 13 度」这种漂亮的数字，
却完全算不出「载具会朝错误方向飞出 308 m」。

**⇒ 凡是改「反馈回路」的方案，开环回放不可信。**

### 3.2 该看什么指标

下次这类改动，**必须先看 `dist_hz` / `vh` 是否发散**：

```
195348:  dist 最大 11.5 m,  vh 最大 6.1 m/s   <- 正常
205641:  dist 最大 308 m,   vh 最大 23.3 m/s  <- 发散
```

只盯 `att_err` / `az_err` 是**会被骗的** —— 205641 的 `att_err` p50 = 1.5 度，
比 195348 的 5.0 度**还好**！因为机头确实稳稳指向了那个错误方向。

**`att_err` 好看不代表飞得对。**

## 7. 剩下的唯一路径

**减小初偏。**

39 趟统计已经证明（`FIVE_TRIALS_ANALYSIS.md:185`）：

| `dist0` | n | `azErr50` 中位 |
|---|---|---|
| `< 50 m` | — | **14.5 度** |
| `> 100 m` | — | **2.0 度** |

`corr(dist0, azErr50) = -0.294` —— **初偏越大，方位角误差反而越小**。

因为初偏大时 `dist` 项主导，`_ah_vec` 方向稳定；初偏小时 `dp` 项主导，
方向在小范围内来回跳。

**⇒ 提高交班精度（`GATE_*` 参数、kOS 侧终端制导）比改方位角通道有意义得多。**
