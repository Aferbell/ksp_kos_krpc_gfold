# 轨迹（G-FOLD 规划）的计算原理 + 两个边界条件问题

> 依据：`dev/solver/gfold_p3p4.py` 源码逐行核对（行号已标）
> 数据：五次试验日志 + 离线复现（`dev/reproduce_gate.py`、`dev/tf_sensitivity.py`）
> **本轮未改任何飞行代码**

---

## 一、轨迹是怎么算出来的（简单版）

### 1.1 一句话

把"从当前位置减速到目标点"写成一个**凸优化问题**，用求解器求出一条
**位置+速度+推力随时间变化**的曲线。**不是**解析公式，是数值优化。

### 1.2 物理模型（源码 line 689-699）

```
x[3:6, n+1] = x[3:6, n] + (dt/2)·((u[n]+g) + (u[n+1]+g))     ← 速度
x[0:3, n+1] = x[0:3, n] + (dt/2)·(x[3:6,n+1] + x[3:6,n])     ← 位置
z[0, n+1]   = z[0, n]   - (α·dt/2)·(s[n] + s[n+1])           ← 质量（烧油）
```

- `x` = 6 维状态：**位置 3 + 速度 3**（目标系：x=上, y=北, z=东）
- `u` = 3 维**推力加速度**（不是净加速度；重力 `g` 单独加）
- `s` = 推力幅值上界（= 油门 × 最大推力 / 质量）
- 质量随油耗递减 ⇒ 这是"燃料最优"的来源

### 1.3 两级结构：P3 找时间，P4 省燃料

| | P3（Minimum Landing Error） | P4（Minimum Fuel Use） |
|---|---|---|
| tf | **固定**为一个预估上限 | = `tf_m` + 余量（探测出来的） |
| 末端位置 | 只要**高度**归零（line 659） | 位置**三轴全零**（line 661） |
| 目标函数 | `Σ‖x[0:3,i]‖·(i/N)` — 尽快靠近 | 最大化落地质量 |
| 产物 | 真正落地的时刻 `tf_m` | **实际要飞的那条轨迹** |

**为什么要两级**：直接问"最少燃料"需要先知道"用多长时间"，
而时间本身是未知的。P3 先用固定时间求"能不能到"，读出到达时刻；
P4 再在这个时间上求最省油。

### 1.4 "无损凸化"：把非凸问题变成凸问题

真实约束"推力幅值 ≤ s **且** 方向受限"是非凸的。G-FOLD 用两招处理：

```
‖u[n]‖ ≤ s[n]                              （line 701，推力幅值上界）
u[0,n] ≥ cos(ang) · s[n]                    （line 703/709，指向锥）
```

第二式是**线性**的，把"锥内"这个非凸约束变成线性的 —— 这就是
"无损凸化"（lossless convexification）。**它保证凸解就是原问题的解。**

### 1.5 指向锥是**时变**的（本项目对原版的修改，line 705-709）

```
ang(n) = 85° + (5° - 85°) · n/(N-2)          ← 从 85° 线性收到 5°
```

**原版全程固定一个锥**，本项目因为入场横速大（可达 350 m/s）会 infeasible，
所以改成"前宽后窄"：**起点允许 85° 大倾角，末端收到 5°**。

### 1.6 其它约束（逐节点）

| 约束 | 行号 | 作用 |
|---|---|---|
| 滑翔角锥 `‖x[1:3]‖ ≤ cot(γ)·x[0]` | 694 | 不许"先横飞再回来" |
| 速度上限 `‖x[3:6]‖ ≤ v_max` | 696 | 数值保护 |
| 不穿地 `x[0,n] ≥ 0` | 711 | |
| **不爬升** `x[3,n] ≤ 0`（**仅 P4**） | 742-743 | 封掉"俯冲-回弹"畸形解 |
| **下降率包络** `x[3,n] ≥ -cap[n]` | 745-746 | 见下 |
| 推力上下界（油门限幅） | 753-755, 771-773 | |

**下降率包络**（`vdesc_cap_vector`，line 191-278）是四道限制取交：

```
① 初速     cap ≥ |vz0|                    （节点 0 不能自相矛盾）
② 减速能力 cap ≥ |vz0| - a_brk·t
③ 自杀点火 cap ≤ sqrt(2·a_brk·h_rem) + 5  （"还来得及刹住"）
④ 巡航速度 cap ≤ v_descent_max (=80)      （用户期望的匀速下滑）
末端最后 40% 时间把 cap 压向 term_vz = 4 m/s
```

**没有它**，纯燃料最优解是 bang-bang：几乎不推地自由落体到最后一两秒猛刹。
**有了它**，得到一条"匀速 -80 m/s 下滑"的平缓剖面 —— 这正是本次五趟看到的。

## 二、Q1：末端有没有考虑"削横速 + 竖直着陆"？

### ✅ **有，而且是硬约束**

从源码逐条读出（这些约束对 **P3 和 P4 都生效**）：

```
line 619  x[3:6, N-1] == zeros(3)          ← 末端【速度三轴全零】(含横速!)
line 620  s[0, N-1] == 0                   ← 末端推力 = 0
line 656  u[:, N-1] == s[0,N-1]·[1,0,0]    ← 末端推力方向【纯竖直】
line 661  x[0:3, N-1] == zeros(3)          ← P4: 末端位置【三轴全零】
```

- **削横速**：`x[4,N-1]=x[5,N-1]=0` —— 水平速度必须归零 ✅
- **竖直着陆**：末端推力方向被钉成 `[1,0,0]`（纯竖直）✅
- **精确落点**：P4 三轴位置全零 ✅

**离线复现证实规划确实这么做了**（173443，tf=18.0）：

```
  node    alt[m]      vz       vh     tilt
    72     32.17   -20.84    4.95    11.15
    74     23.88   -16.02    3.30     9.10
    76     18.28    -7.21    1.48     7.05
    77     17.25    -1.96    0.59     6.03
    78     17.01    -0.12    0.20     5.00
    79     17.00    -0.00    0.00     0.00   ← 速度、横速、倾角全归零
```

**规划自己把 vz / vh 都收到 0，倾角也收到 0。这一条没有问题。**

### ⚠️ 但有两个真实的**实现层**问题

#### 问题 A：末端"速度归零"点就在**触地点**上，几乎没有余量

```
求解器高度口径：x[0]=0  ⟺  alt = TARGET_ALT = 17 m
控制器的停机判据：alt ≤ TARGET_ALT + 1.0 = 18 m
```

⇒ **规划要求的"速度归零"点（alt=17 m）与载具触地点（alt≤18 m）几乎重合。**
载具在"还没到规划刹停点"时就接地了，于是**继承了规划倒数第二节点的速度**。

实测落地垂速（六趟）：

```
  -1.64  -6.64  -6.75  -9.55  -10.63  -10.78 m/s
```

规划在最后一个记录点（alt≈17.9 m）自己还有 `plan_vz = -2.2 ~ -9.3`。
⇒ **落地偏硬不是"规划没考虑"，而是"考虑的刹车距离太短"。**

**⇒ 可优化点**：把目标点抬高（或让规划在 alt = 17 m **之上**就完成归零），
给"最后一段"留出真正的减速余量。

#### 问题 B：规划的自由度（85°）大于执行器的自由度（35°）——**结构性不一致**

```
求解器的指向锥：  85°（起点） → 5°（末端）      [line 705-709]
控制器的倾角上限：35°（高空） → 5°（低空）      TILT_CAP_HI / LO
```

⇒ **规划以为可以倾斜 85°，但控制器只允许 35°。**
规划用掉的自由度，控制器兑现不了。

这正是上一轮量化到的饱和：**42~56% 的帧需求倾角被削平**。
**规划与执行器的锥必须一致**，否则规划再优也飞不出来。

## 三、Q2：起点有没有考虑"入场时自带的倾角"？

### ❌ **没有。求解器完全不知道载具的入场姿态。**

```
接口：solve_p3p4_state(x0, mass, ...)
x0 = [px, py, pz, vx, vy, vz]     ← 只有 6 个数：位置 3 + 速度 3
                                    【没有姿态角、没有角速度】
```

而约束**强制**首帧推力竖直：

```
line 655  u[:, 0] == s[0,0]·[1,0,0]     ← 起点推力方向 = 纯竖直
```

⇒ **规划的隐含假设是"t=0 时机头朝正上方"。**

源码注释里记录了这个决定的来历（line 623-654）：原先删掉过这条，
结果求解器把节点 0 解成 **85° 倾角**，而交接时载具实际是 24.5°，
要求它 0.2 s 内转 60.5° —— 物理不可能，于是前 3 帧油门几乎全用在竖直减速，
把 vz 刹过头 ⇒ 完全不跟踪。恢复这条约束后节点 0 变竖直，**首帧就变成可执行的**。

**⇒ 所以"强制起点竖直"是【有意的设计】，目的是让首帧可执行。**

### ⚠️ 但这带来一个新问题：**节点 0→1 的倾角跳变**

节点 0 被强制竖直，而节点 1 已经要开始倾斜。实测这个跳变**远超物理能力**：

```
=== 173443（tf 扫描，离线复现）===
     tf   peak tilt   node0    node1    node2   node1 所需角速率
  18.00      16.79     0.00    16.17    16.79      71.0 deg/s
  18.50      13.89     0.00    13.89    13.70      59.3
  19.00      12.00     0.00    11.89    11.67      49.4
  20.00      10.54     0.00     9.15     8.93      36.1
  22.00       8.81     0.00     5.99     5.80      21.5

=== 164053 ===
  18.00      48.67     0.00    48.67    33.51     213.6 deg/s
  18.50      11.40     0.00    11.40    11.14      48.7
  20.00       7.79     0.00     7.79     7.64      30.8

  物理角速率上限（alpha=14.6 deg/s², headroom=45°）≈ 36 deg/s
```

**⇒ 大部分 tf 下，规划要求节点 0→1 之间转 21~213 deg/s，而物理上限只有 36。**
**规划要求了一个空气动力学上做不出来的动作。**

而且 `dt = tf/(N-1) ≈ 0.22 s` 只是一个离散节点的间隔 ——
**规划内部默认"姿态能瞬时跟上推力方向"，没有把姿态动力学写进模型。**

### ⚠️ 还有一个**闸门失效**的迹象

求解器有规划质量闸门（line 102）：

```
_PLAN_TILT_MAX_DEG = 20.0   # 规划峰值倾角 <= 20° 才采信
```

逻辑（line 1007-1041）：探测可行 tf 时若峰值倾角 > 20°，继续向上探；
若 16 次（= 8 s）都找不到合格解，**退回第一个可行解**（保底）。

但实飞日志显示被飞的那条规划**峰值倾角远超 20°**：

```
  trial      日志 plan_tilt_j max    闸门（20°）
  164053           16.30              PASS
  172942           16.95              PASS
  172711           69.83              FAIL
  172435           43.39              FAIL
  173133           73.96              FAIL
  173443           77.87              FAIL
```

**⇒ 四趟的规划未通过 20° 闸门，走的是"退回第一个可行解"的兜底分支。**

**⚠️ 诚实说明**：我用日志的交班状态离线复现时，求解器选出的 tf
与实飞不同（实飞 173443 是 tf=17.25，我的复现选 18.00），
复现出的规划峰值倾角只有 16.79°（合格）。
**两者不一致的原因尚未查清**（可能是 `est_time` 外推后的 x0 略有差异，
以及 P3 估出的 `tf_m` 不同导致探测序列不同）。
⇒ "闸门在实飞里为什么没拦住" **需要进一步确认**，暂不作为结论。

## 四、结论与建议

### 两个问题的直接回答

| 问题 | 回答 |
|---|---|
| **Q1 末端** | ✅ **有**考虑削横速（末速三轴归零）与竖直着陆（末推力竖直），且是硬约束。<br>⚠️ 但"速度归零点"就在触地点上（alt=17 m），**刹车余量几乎为零** ⇒ 落地偏硬。<br>❌ 且规划的自由度（85° 锥）**大于**控制器的（35° 上限）⇒ 规划飞不出来。 |
| **Q2 起点** | ❌ **没有**考虑入场倾角 —— 接口只传位置+速度，**没有姿态**。<br>✅ 但**强制起点推力竖直**是有意设计（否则首帧要求 85° 急转，物理不可能）。<br>⚠️ 代价是**节点 0→1 的倾角跳变**要求 21~213 deg/s，而物理上限只有 36。 |

### 建议（按性价比）

| 优先级 | 动作 | 依据 |
|---|---|---|
| **1** | **统一"规划锥"与"控制器倾角上限"** | 求解器 85° vs 控制器 35° —— 结构性不一致，直接导致 42~56% 帧饱和 |
| **2** | **抬高末端归零点**（目标点抬高或让规划提前归零） | 现在归零点 = 触点，落地 vz −1.6~−10.8 |
| **3** | **把姿态动力学写进规划约束**（限制逐节点倾角变化率） | 节点 0→1 要求 21~213 deg/s vs 物理 36 |
| 4 | 查清 20° 闸门在实飞中为何未生效 | 四趟 `plan_tilt_j` > 43° |

### 一句话总结

**规划本身是"对"的（末端约束齐全），问题在于它和实际执行器"说的不是同一种语言"**：
规划用 85° 锥 + 瞬时姿态 + 触地归零，
而执行器只有 35° 上限 + 约 36 deg/s 的转动能力 + 需要提前刹车的余量。
