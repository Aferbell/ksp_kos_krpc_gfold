### 4.3 候选A：水平 eguidance（**已实现**）

**推导（这是理解后续一切的基础）**：设 `dp = x_plan - x_veh`、`dve = v_plan - v_veh`，
控制律 `a_h = u_h + kv*dve + kp*dp`，则

```
d(dp)/dt  = dve
d(dve)/dt = u_h - a_h = -(kv*dve + kp*dp)      <- u_h 完全抵消
=> 标准二阶： wn = sqrt(kp) ,  zeta = kv/(2*sqrt(kp))
```

eguidance 取 `kv = 4/T, kp = 6/T^2` ⇒ **`zeta = 4/(2*sqrt(6)) = 0.8165` 与 T 无关**。
旧律 `kv = min(1.25, 1/tgo_eff)`（**竖直** tgo）配 `kp = 0.25` 常数，
实飞 `tgo_eff` 中位 7.63 s ⇒ `kv = 0.132` ⇒ **`zeta = 0.131`（严重欠阻尼）**——
这就是"6~7 次阈值穿越、43% 帧反向"那个极限环的根因。

相位裕度（`L(s)=(kp+kv*s)/(s^2(1+tau*s))`，实测姿态滞后 `tau=1.31 s`）：

| 律 | PM(tau=1.31) |
|---|---|
| 旧律 kv=0.132 kp=0.25 | **-17.7 deg（不稳定）** |
| 候选A T=4 | **+18.7 deg** |
| 候选A T=8 | +36.7 deg |

**所以 `CA_T_MIN=4.0` 是按相位裕度定的，不是拍的。**

## 6. 候选A 的两个已量化缺口（第二步 / 第三步）

### 6.1 **加速度有限没有被考虑**（第二步）

代码用 `_ca_T = clamp(2*_perr/_verr, 4, 8)` —— **纯运动学，全程没有出现 `a_h_max`**。
它随后要求的水平加速度是 `a_dem = |4V/T - 6D/T^2|`，而能力是 `a_h_max = av_up*tan(tf_cap)`。

实测（`152048`，89 帧）：

```
dem/cap 比值      : p10=0.046  p50=0.473  p90=1.222  max=8.100
超过能力的帧      : 14/89 = 15.7%
最坏一帧          : D=29.74 V=49.97 T=4.00 -> demand=38.82  cap=4.79  ratio=8.1
即使放到 T=8     : 仍有 8/89 = 9.0% 超能力
```

**根因：`f(T) = 6D/T^2 - 4V/T` 是【非单调】的**
```
f(0+) = +inf ; 过零在 T = 1.5*D/V ; 极小值 -2V^2/(3D) 在 T = 3*D/V ; T->inf 时 f->0
=> |f| <= a_max 只在【两端】成立（T 接近 1.5D/V，或 T 足够大），中间是"死亡区"
```

最坏那帧（D=29.74, V=49.97, a_max=4.79）逐点验证：

| T | f | 比值 | |
|---|---|---|---|
| 4.00（**代码会用**） | -38.82 | 8.10 | 不可行 |
| 8.00（`CA_T_MAX`） | -22.20 | 4.63 | 不可行 |
| 20.0 | -9.55 | 1.99 | 不可行 |
| **60.0** | **-3.28** | **0.685** | **可行** |

**⇒ 这一帧唯一可行的 T 约 60 s，而代码被钳在 [4,8] 永远到不了。
⇒ 正确的 T 应由可行性反解：解 `|4V/T - 6D/T^2| <= a_max`，取可行区间内的 T；
无可行 T 时退化为"最小超额"并把该情形记为饱和（这本身就是有价值的诊断量）。**

### 6.2 **末端加速度约束 a(T)=0 没有实现**（第三步）

代码用的是**三次** eguidance（`a(T)` 自由），不是**四次**：

| | kv | kp | a(T) |
|---|---|---|---|
| **代码用的（三次）** | `4/T` | `6/T^2` | **自由** |
| 末段归零的（四次） | `6/T` | `12/T^2` | **= 0** |

代码剖面的末端值 `a(T) = -6D/T^2 + 2V/T`：

```
|a(T)| : p10=0.327  p50=1.137  p90=8.281  max=20.481
|a(T)| < 0.1 的帧 : 2/89 = 2.2%
```

而且末段被 **`TILT_CAP_LO = 5.0 deg`** 硬钉住：

| t | alt | tf_cap | tilt_cmd | a_cmd_h |
|---|---|---|---|---|
| 17.21 | 22.79 | 6.43 | 6.43 | 4.794 |
| 17.39 | 18.76 | 5.00 | 5.00 | 4.246 |
| 17.57 | 14.55 | 5.00 | 5.00 | 3.998 |

**验算**：`tan(5 deg) = 0.0875`，末帧 `av_up = 45.69` ⇒ `0.0875*45.69 = 3.998` **= 日志 `a_cmd_h`，逐位吻合**。

**⚠️ 设计冲突（必须由用户决定）**：`TILT_CAP_LO=5 deg` 是用户在第 15(a) 步为了"落地时仍保留横向修正能力"**特意要的**，
而 `a(T)=0` 要求落地瞬间水平加速度为 0（倾角竖直）。**两者物理上互斥。**
建议按高度分开：`alt > 20 m` 保留 5 deg 下限，`alt < 5 m` 允许收到 0。**但需用户确认。**

## 7. 下一步（用户指定顺序）

### 第一步：治姿态过冲（**先做**）

1. **PID 是否饱和**：`pid_sat_x` / `pid_sat_z` / `pid_sat_run`、`pid_out_x` / `pid_out_z`。

3. **倾角速率限幅是否在削**：`tf_slew_allow`（5~14 deg/s）与 `d(tilt_cmd)/dt` 对比；
   若后者长期贴住前者，说明限速器在削，指令被拖成斜坡。
4. **前馈/阻尼项**：`ff_x` / `ff_y` 是否被 `FF_CLAMP_RAD=0.12` 限死（`FF_GAIN=0.60`）；
   `rate_x` / `rate_y`（D 项用的真实角速度）与 `rho` 关系。
5. **参考方向速率限制器**：`ref_slew` / `ref_clip`（`REF_SLEW_ENABLE=True`）。
6. **重点是"指令本身是否超过物理能力"还是"PID 调得不够"** —— 这两者的修法完全不同。

**相关常量**：`CTRL_X_ROT_KP=5` / `CTRL_X_ROT_KD=2.5`、`RATE_D_ENABLE=True`、`RATE_D_GAIN=0.78`、
`FF_ENABLE=True`、`FF_GAIN=0.60`、`FF_CLAMP_RAD=0.12`、`TAU_SCHED_ENABLE=True`。

**本次新增的 4 列（候选A 诊断）**：

| 列 | 含义 | 判读 |
|---|---|---|
| `ca_T` | 水平时间尺度 `2*perr/verr` 钳位 [4,8] | 贴 4 = 最强档；贴 8 = 最弱档 |

**从日志反推编译常数的方法**（很好用）：
