## 2. 根因：预热用了**错误的速度外推**

### 复现（`dev/krpc/diag_prewarm_track.py`）

按实飞真实时序（**预热用预测状态解 → 再用实际状态 track**）：

```
预热状态 alt=6237, vz=-390.7
预测 3.17 s 后到门: h=4963.2 (alt=5000)
预热解 tf=20.00

用实际状态 track:
  step0 n_i=1.831  a_cmd=[2.44, 0.0, 0.0]  tilt= 0.00  thr=0.050
  step1 n_i=2.708  a_cmd=[2.44, 0.0, 0.0]  tilt= 0.00  thr=0.050
  ...
```

**与日志完全一致**（`a_up=2.38 / a_h=0 / thr=0.05`）⇒ 根因确认。

### 机制

`_start_prewarm` 旧代码：

```python
est_t = (alt - GATE_ALT) / |vz|
x0_pred = [tp[0] - |vz|*est_t, tp[1], tp[2], tv[0], tv[1], tv[2]]
#                                             ^^^^^ 速度【原样不动】
```

**"高度推到门、速度不变"这个假设是错的**：
- 预热在 alt≈6237 触发，此时 kOS 段1 还在**持续减速**（实测 `vz≈-390`）
- 到门（alt=5000）时实际 `vz` 只有 **-286**（kOS 已减了 100 m/s）
- 但预测仍用 -390 ⇒ 轨迹按**"掉得快得多"**来规划
- ⇒ 轨迹起点与实际状态严重不匹配
- ⇒ `find_nearest_index` 定位偏离、PD 项被"未来高度差"污染
- ⇒ `target_a` 竖直分量变负
- ⇒ `conic_clamp` 返回纯竖直 `[min_mag, 0, 0]`
- ⇒ **`a_cmd_h=0`、`thr=0.05`、姿态被命令竖直** ⇒ 完全不跟踪

## 3. 修正（两处）

### 3.1 预热不再做会失真的速度外推

```python
# 前：x0_pred = [tp[0] - |vz|*est_t, ...]     ← 高度推到门
# 后：x0_pred = [tp[0], tp[1], tp[2], ...]    ← 用当前状态，不外推
```

预热的价值是**"把求解耗时藏进 kOS 飞行段"**，不是"预知未来状态"。
起步点与实际交接点的差异，交给下面的一致性检查处理。

### 3.2 新增**预热结果一致性检查**（关键）

即便不外推，预热是在门上方解的，到门时本机已前进 2~3 s。
⇒ 在 `run()` 里检查预热轨迹的起点与实际交接点的差异：

```python
_gap_alt = abs(plan['x'][0,0] - (alt - TARGET_ALT))
_gap_v   = abs(plan['x'][3,0] - vz)
if _gap_alt > PREWARM_MAX_ALT_GAP or _gap_v > PREWARM_MAX_V_GAP:
    # 弃用预热，重新解算（codegen 只要 0.17 s）
    self.plan = None
```

新增常量：

```python
PREWARM_MAX_ALT_GAP = 150.0   # m
PREWARM_MAX_V_GAP   = 40.0    # m/s
```

**宁可多花 0.17 s 重解，也不要拿一条起点错位的轨迹去飞。**
