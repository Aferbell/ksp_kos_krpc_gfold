## 0. 一句话结论

> 当前 bang-bang 制导**成功地把速度刹到了 0** —— 但它是在 **5100 m 高空、离目标 3.4 km** 处刹停的，
> 然后 `e_tgo → 0` 把推力方向硬切到 `upv`，**净加速度 +105 m/s² 竖直向上**，
> 把火箭从 5.1 km 一路推到 **24.4 km**，耗光 103 t 推进剂，最后自由落体以 **359 m/s** 撞地。
>
> **`T_burn = 1.15·|v|/a_net` 只闭合了"终端速度=0"，完全没有闭合"终端位置=目标点"。**
> 这正是交接文档 §5.1 那条"E 制导只有 6 个标量约束"铁律的**同一个病**，只是换了个马甲：
> 旧的 E 制导缺**倾角**约束；新的 bang-bang 缺**位置**约束。

### 1.2 病根链（四条，按因果顺序）

1. **`T_burn` 的物理含义错了。**
   `T_burn = 1.15·|v|/a_net` 是**"把速度归零所需时间"**。
   它**不含任何到目标的距离信息**。以 917 m/s、62 m/s² 计，刹停需 ~15 s、消耗 ~14 km 的冲量，
   而当时到目标的水平距离只有 8.2 km、高度 10.1 km。
   ⇒ **速度先归零，位置还没到。** 这正是实测 idx293 的状态。

2. **`e_tgo → 0` 之后没有"着陆"这一态。**
   `dir_cmd = dir_retro·(1−dir_w) + upv·dir_w`，`e_tgo=0 ⇒ dir_w=1 ⇒ dir_cmd = upv`，
   而 `a_cmd = dir_cmd · a_net = upv · a_net`（正值、满推力、竖直向上）。
   ⇒ **`T_burn` 到期不是"该着陆了"，而是"该以满推力垂直加速上升了"。**
   代码里没有任何"这是一次悬停/着陆"的分支。

3. **兜底判据 `v_now:mag < 5 or h_gnd < 8` 是"速度门"，不是"任务门"。**
   idx293 触发它时 `h_gnd = 5080 m`，`term_k·(−term_v − vz) = 2·(3.86−2) = 3.72 m/s²`，
   对应节流 0.157 —— 几乎关车。**在 5 km 高空"速度小于 5 m/s"被当成了着陆成功**。
   ⇒ 判据缺少 `h_gnd` 侧的必要条件：速度小 **且** 贴近地面才算落地。

4. **水平位置全程无人管。**
   `dist_hz` 序列：8237 → 3421 → **3401（最小值）** → 5713（终点）。
   **横向误差从 3.4 km 反而涨回 5.7 km**，因为主段 `dir_retro = −v̂` 只沿着速度反向，
   与"目标在哪"无关；一旦速度反向被抵消，横向就没有任何项在收敛它。

### 1.3 与交接文档 §5.1 的关系（重要修正）

交接文档说"病根是 E 制导缺倾角约束"。**那把倾角补上了（`tilt_ref` 确实单调降到了 0，判据通过）**，
但立刻暴露了**下一层缺失**：

| 代次 | 制导律 | 闭合了什么 | 缺什么 | 结局 |
|---|---|---|---|---|
| 旧 | E 制导（6 标量） | 位置 + 速度 | **倾角** | 落偏、倾角到不了 0 |
| 现 | bang-bang | **速度**（\|\|v\|\|→0） | **位置** + 末端推力大小 | 刹停在半空、24 km 爬升、撞地 |

> **规律**：每换一次律，都只闭合了一部分边界条件，而**缺的那一维就变成下一趟的失败模式**。
> 所以这次**不能只修补一个标量**，必须一次把**位置、速度、倾角、推力幅值**四条都纳入同一个可解结构。

### 2.1 可以直接借鉴（★ 首选）

#### ★ A. G-FOLD 的 **问题结构**（不是它的求解器）
`90_代码与源码/gfold_Cpp_G-FOLD_implementation/gfold-master/src/gfold.cpp`

这是**唯一一个把"高能量自杀式制动 + 定点着陆"写成完整约束集**的参考。它的骨架：

```
变量：x = [r, ṙ] (6×N) ,  u = T/m (3×N) ,  σ = |T|/m ,  z = ln(m)
目标：P3 = 最小化终端落点误差 ‖E·r(tf) − q‖
      P4 = 再最小化燃料 Σσ
约束（Eq.8/9/17/34）：
  ① 初始 r0, ṙ0 等式
  ② 终端高度 = 0、终端速度 = 0  ← **位置和速度都钉死**
  ③ 滑翔角锥 ‖E(r − rf)‖ ≤ cᵀ(r − rf)   ← **天然给出"从上方接近"**
  ④ 动力学 x+ = x + (A x + B(g + u))Δt
  ⑤ 质量 z+ = z − ασ
  ⑥ |u| ≤ σ ≤ ρ2·e^{−z0}·(1 − z_diff)   ← 推力上界（对数质量变量，无损凸化）
  ⑦ 推力指向锥 n̂ᵀu ≥ cos(θ)·σ          ← **倾角/推力指向约束**
  ⑧ 速度上界 |ṙ| ≤ V_max
```

**可直接抄的三件事**（不需要解 SOCP）：

1. **约束③ 滑翔角锥** → 直接写成 kOS 里的一条**状态检查 + 指令投影**。
   它就是"火箭必须从目标点正上方的锥内接近" —— 治的正是本趟"横向 5.7 km"的病。
2. **约束⑦ 推力指向锥** → 直接限制 `dir_cmd` 与 `upv` 的夹角，替代现在按 `lqr_tmax/lqr_tmax_hi` 的散装限幅。
3. **约束② 终端位置与速度同时为 0** → 这是现在**完全缺失**的那一维。

> **不能抄的**：`cvx::ecos::ECOSSolver`、`socp.addConstraint`、Eigen 矩阵。
> kOS 没有任何求解器、没有矩阵、没有 Eigen。**只抄约束的物理含义，不抄求解方式。**

#### ★ B. 金字塔接近角论文的**分段解析解**（含倾角不等式的闭式解）
`notes/2026_金字塔形接近角约束最优动力下降制导_解析解首选.md`

这是知识库里**唯一给出"带倾角不等式路径约束"的闭式最优解**的文献，而且解的形式极其适合 kOS：

- **无约束弧**（`u*` 对 `t_go` 是线性的）：
  $$u^* = -\begin{bmatrix} L_1 t_{go1} + g_n \\ M_1 t_{go2} + g_t \\ N_1 t_{gof} + N_2\end{bmatrix}$$
- **约束激活时，法向分量恰好抵消重力分量**：
  $$u_n^* = -g_n,\qquad u_t^* = -g_t$$
  （原文 Eq.32/45，并在 §IV.F 证明"已上约束就不会离开约束"）
- **切换时刻有闭式解**（原文 Eq.64/72）：
  $$t_{go2} = -\frac{3r_t(t)}{V_t(t)},\qquad t_{go1} = -\frac{3r_n(t)}{V_n(t)}$$
- **最终着陆段沿约束线的最优控制**（原文 Eq.51）：
  $$u_r^* = -\frac{6r_r(t)}{t_{gof}^2} - \frac{4V_r(t)}{t_{gof}} - g_r$$
  **这个式子的结构和 E 制导一模一样**（6/r² 位置项 + 4/T 速度项 + 重力前馈），
  说明**竖直通道的正确形式是 `−6h/T² − 4vz/T − g`**，
  而现在的实现是 `a_net`（常数满推力）—— 这就是"刹停后不知道该怎么办"的数学根源。
- **最优末时间从 4 次多项式求根**（原文 Eq.82）：
  $$\|\mathbf{g}'\|^2 t_f^4 - 4V_r^2(t_0)t_f^2 - 24r_r(t_0)V_r(t_0)t_f - 36r_r^2(t_0) = 0$$
- **关键结论 Eq.83**：**约束激活会让最优末时间变短** `0 ≤ t̄̄_f* ≤ t̄_f* ≤ t_f*`。

**可直接抄**：上面这 5 个闭式解在 kOS 里都是**几次乘除 + 一个 4 次求根**（Newton 3~4 步即可）。
**这是本方案的核心替换件。**

#### ★ C. 航空学报 2024 的**约束动态调整**与**终端时间方程**

`notes/2024_航空学报_火箭着陆段能量管理与轨迹优化技术_推力角与轨迹倾斜角动态调整.md`

- **推力角/轨迹倾斜角随节点线性放松**（原文 Eq.14）：
  $$\theta_i = \frac{N-k}{N-1}\theta_{i\max},\qquad \upsilon = \frac{N-k}{N-1}\upsilon_{\max}$$
  即"**初始允许大倾角、临近着陆越来越严**"。这一条现在代码里是散装的
  （`lqr_tmax=30` / `lqr_tmax_hi=50` / `th_by_rate`），可以统一成这一条**随时间线性收紧**的式子。
- **剩余时间 4 次方程**（原文 Eq.9）：
  $$\frac{g^2}{2}t_g^4 - 4[(v_0{+}v_f)^T(v_0{+}v_f) - v_0^Tv_f]t_g^2 - 24(r_0{-}r_f)^T(v_0{+}v_f)t_g - 36(r_0{-}r_f)^T(r_0{-}r_f) = 0$$
  比金字塔那篇更完整（含 `v_f` 项）。**求根即得 T，不写死 4.8 s。**
- **四/五次多项式解析解**（原文 Eq.6~8）供**给初值**，不做在线跟踪。
- **仿真参数对照**：Falcon 9 级、比冲 282 s、节流 50~100%、终端姿态角偏差 < 1.5°、在线 < 1 s。
  **注意其初始速度只有 200 m/s 量级**（表 1：`[50, -200, 2]`），**和本场景 917 m/s 差一个量级**——见 §2.3。

#### ★ D. Apollo AGC 真实工程实现（`TTF` 的处理方式）
`01_原典_E制导与PEG/Apollo11_AGC月面着陆制导方程源码_Luminary099.txt`

真实飞行软件的做法（而非论文的理想式）：

- **制导律**（代数等价于 APDG）：
  $$a_{cmd} = A_{DG} + \frac{3}{4}\cdot\frac{(R_{DG}-R_G)/T_{TF}/8 + V_{DG}+V_G}{T_{TF}/8}
  \;\equiv\; A_{DG} + \frac{6(V_{DG}+V_G)}{T_{TF}} + \frac{12(R_{DG}-R_G)}{T_{TF}^2}$$
  **`TTF` 是负数** ⇒ 速度项是**负反馈阻尼**、位置项是**正增益**。
- **T 不是闭式给的，是解 3 次方程**，用 `ROOTPSRS` Newton 迭代，
  **以上一轮的 `TTF/8` 作初值（warm start）**，且**只允许 8 次迭代**。
  系数：`A0 = -24(RDG2-RGU2)/64`、`A1 = (6*VGU2+18*VDG2)/8`、`A2 = 6*ADG2`、`A3 = 8*JDG2`。
- **`T→0` 奇异的工程兜底**：`LEADTIME` 增益削减 + 显式发散保护
  ```agc
  CS TTF/8
  AD LEADTIME    # LEADTIME IS A NEGATIVE NUMBER
  AD POSMAX      # SAFEGUARD THE COMPUTATIONS THAT FOLLOW
  TS L           # BY FORCING -TTF*LEADTIME > OR = ZERO
  ```
  ⇒ **kOS 里对应"给 T 设下限 + 增益限幅"，且必须显式写。**

> **这一条最有价值**：它证明**"每帧用上一帧的 T 做初值解一个 3~4 次方程"在 1969 年的
> 2 MHz 机器上就能跑**。kOS 完全跑得动 —— **`T_burn` 根本没有必要"冻结"**。
> 现在把它冻结成常数，正是丧失位置约束的直接原因。

**子代理复核补充（可直接移植的两个式子）**：

1. **Klumpp Eq.(7) 的精确形式**（`T` 为负）：
   $$a_{cmd} = \frac{12(R_{TG}-R_G)}{T^2} + \frac{6(V_{TG}+V_G)}{T} + A_{TG}$$
   增益 `K_R = 12`、`K_V = −6`。**AGC 里"as programmed"的写法经符号验算与它完全等价**。
   kOS 里就是 **3 次向量运算**，无需矩阵库。
2. **T 的 3 次方程**（Klumpp Eq.12），AGC 每帧热启动 Newton 求解、**上限 8 次迭代**：
   $$J_{TGz}T^3 + 6A_{TGz}T^2 + (18V_{TGz}+6V_{Gz})T + 24(R_{TGz}-R_{Gz}) = 0$$
   **移植时必须复现 AGC 的 `/8`、`/64`、`3/4`、`3/8` 归一化** ——
   `ROOTPSRS` 明确声明 `|x·A(I)| < 1` 是**调用方的责任**，它自己不做溢出检查。
3. **`T→0` 的工程兜底（原文注释，可直接照抄语义）**：
   ```agc
   CS TTF/8
   AD LEADTIME    # LEADTIME IS A NEGATIVE NUMBER
   AD POSMAX      # SAFEGUARD THE COMPUTATIONS THAT FOLLOW
   TS L           # BY FORCING -TTF*LEADTIME > OR = ZERO
   ```
   ⇒ **kOS 对应"给 T 设下限 + 增益限幅，且必须显式写"**。Apollo **没有任何数值 clamp**，
   它的解法是"**永远不飞到 T=0**"：`T<0` 就交班给纯速度环 P66。
   **这一条正对着本趟的失败** —— 我们的 `e_tgo` 一路跑到 0 还在用主制导，等于踩中了 Apollo 明确规避的坑。

### 2.2 只能借鉴思想、不能移植代码

#### E. 无损凸化 / SOCP（PythonRobotics、lcvx、LosslessConv、SCvx-6DoF）
`90_代码与源码/PythonRobotics_rocket_powered_landing.py`、`lcvx-master/ifac_wc_2020/landing.py`、

- **核心思想（可借鉴）**：把非凸的推力下界 `T_min ≤ |T| ≤ T_max` 用**松弛变量 `σ` + 无损凸化**变成凸的；
  `|u| ≤ σ`、`μ1 ≤ σ ≤ μ2`。**物理含义**：把"推力大小"独立出来当变量，方向与大小解耦。
  ⇒ **kOS 里可借鉴为"把推力幅值当作显式决策量"**（现在是隐含由 `a_net` 满推力）。
- **终端姿态约束的凸化**（Szmuk 2018 Eq.8/9）：
  $$\cos\theta(t) = 1 - 2(q_2^2+q_3^2) \;\Longrightarrow\; \cos\theta_{\max} \le 1 - 2(q_2^2+q_3^2)$$
  **注意**：这是**四元数二次型**写的倾角约束，kOS 没有四元数 → **只能取"推力方向与 up 的夹角"等价形式**。
- **SCvx 的三个工程技巧（可借鉴）**：
  1. **信赖域** `‖x−x_last‖₁ ≤ δ`（防线性化发散）
  2. **虚拟控制** `ν` 加在动力学里 + 高权重罚 `W_ν = 1e5`（防"人为不可行"）
  3. **信任域半径逐次放大** `w_delta *= 1.5`
  ⇒ kOS 里对应"**每帧指令相对上帧的限幅**" + "**用上一帧解做热启动**"，
  这正好就是现在 `ref_wmax=12°/s` 限速器在做的事 —— **可以保留并强化**。
- **不能移植**：`cvxpy`、`ECOS`、`Gurobi`、`odeint`、`np.linalg`。**一个都不能用。**

### 2.3 明确**不适用**本场景的

| 文献/结论 | 为什么不适用 |
|---|---|
| 四次/五次多项式制导（北航 2025、航空学报 2024 Eq.6-8） | 已用实测核算否定：需 `T ≥ 31.8 s` 而实机只有 19.7 s（a_note §19.2）。**其仿真初速仅 200 m/s 量级，比本场景低一个量级**，不能直接套 |
| APDG / E 制导做主制导 | 只闭合 6 个标量（位置+速度），**倾角与推力幅值是盲区**（分岔法 2025 §I 原文、Klumpp R-695 的 E 矩阵结构）。**且在 T≈20 s 时位置增益 `12/T²` 会饱和 7 倍**（见 §3.2 修正） |

## 3. 重构方案

### 3.0 设计原则（三条）

1. **每一帧都重新求解"从现在到落点"的完整两点边值问题**，不再"点火时冻结 T_burn"。
   依据：Apollo AGC 在 1969 年的机器上就是每帧解 3 次方程（§2.1-D）。
2. **位置、速度、倾角、推力幅值四条约束必须同时在场**，缺一条就会重演历史（§1.3）。
3. **必须有"够不到目标"的降级态**，保证不出现"爬到 24 km"这种发散（§2.2-F）。

### 3.1 新的状态机（替换现在的 `ignited / pl_seg` 两态）

```
 APPROACH  ──制动──>  BRAKE  ──速度进包线──>  TERMINAL  ──触地──>  LANDED
     │                  │                      │
     │                  └──高度/速度异常──> ABORT_DESCENT（降级：保证落近）
     └──能量不足──> ABORT_DESCENT
```

| 状态 | 进入条件 | 制导律 | 结束条件 |
|---|---|---|---|
| `APPROACH` | 点火前/刚点火 | 滑翔角锥 + 制动 | 速度进 `TERMINAL` 包线 |
| `BRAKE` | 主制动 | 金字塔无约束弧（对 `t_go` 线性） | `h_gnd < h_term` **且** `vz > −v_term_max` |
| `TERMINAL` | **贴近地面** | 金字塔线约束解 `u_r = −6h/T² − 4vz/T − g` | `h_gnd ≤ 0` |
| `LANDED` | `h_gnd ≤ 0` | 节流 0 | — |

**关键修改**：`TERMINAL` 的进入判据**必须同时含高度**：
```ks
// 现在（错的）：只看速度
if v_now:mag < 5 or h_gnd < 8 { ... }
// 改成：速度小 **且** 已经贴近地面，才算进入终端
if h_gnd < term_gate_alt and v_now:mag < term_gate_v { set phase to 2. }
```
其中 `term_gate_alt` 取几十米量级（本场景目标 `target_alt=36.8`），
而不是现在的"5 km 高空只要速度<5 就算终端"。

### 3.2 核心制导律（替换 §3.3 的 bang-bang）

> **⚠️ 本节经过一次重要修正，必读。**
> 初稿曾建议把 `a_cmd = a_net`（常数满推力）直接换成 `6r/T² − 4v/T`（E 制导/最小努力解）。
> **实测核算否定了这个做法**：在点火状态（|r|≈13000 m、|v|≈917 m/s、T≈20 s）下
> ```
> 12·|r|/T² = 12·13000/400 = 390 m/s²
>  6·|v|/T  =  6·917/20    = 275 m/s²
>                    合计 ≈ 665 m/s²   vs   a_net ≈ 62 m/s²
> ```
> ⇒ **饱和 7 倍以上**。Apollo 在 P63 段遇到的正是这个（子代理独立复核：
> Eq.(7) 给出 221 m/s² 对 50 m/s²，4.4 倍缺口），AGC 的处置是**让它饱和**。
> **所以"无约束弧"的解在本场景的主制动段不可用** —— 它只在 T 足够大或已贴近约束面时才可行。
>
> **关键区分（本方案的核心结构）**：
> | 弧 | 控制形式 | 量级 | 本场景可用性 |
> |---|---|---|---|
> | **无约束弧** | `−6r/T² − 4v/T − g` | `T=20 s` 时 **665 m/s²** | ❌ 主制动段饱和 |
> | **约束弧（在约束面上）** | 法向 `u_n=−g_n`、切向 `u_t=−g_t` | **≈\|g\| = 9.8 m/s²** | ✅ 几乎不耗推力 |
> | **约束弧沿自由轴** | `−6r_r/T² − 4V_r/T − g_r` | `h=5080, T=20` → **76 m/s²** | ✅ 恰好落在 `a_net≈82` 内 |
>
> **⇒ 正解是"让火箭贴着滑翔角锥飞"**，而不是"用 E 制导算方向"。
> 锥面上的法向/切向只需 9.8 m/s²（抵消重力），姿态自然被约束成"朝目标点方向倾斜"；
> 唯一需要大推力的是**沿着陆轴的那一维**，而它在大 T 下恰好可行。
> **这正是金字塔论文 §IV.F 证明的"约束一旦激活就不会离开"的工程价值。**

**三段合一的闭式律**（金字塔论文 Eq.73/75 的工程简化版，全用 kOS 可算的向量运算）：

```
每帧：
  r = r_tgt                       // 已经算好的"到抬高瞄准点"的矢量
  v = v_now                       // 对地速度
  h = h_aim,  vh = 水平速度,  vz = 竖直速度

  // ---- ① 真实 T：从 4 次方程求根（航空学报 Eq.9），Newton 3~4 步，上帧值热启动
  T = solve_tgo(r, v, g, T_prev)

  // ---- ② 判断当前在哪个"弧"，用对应的控制形式（这是修正后的核心）----
  //   锥内（未贴约束）且 T 够大 ⇒ 无约束弧；否则贴约束面飞
  if cone_active or (desired_tilt > tilt_max_now) {
      // ===== 约束弧：贴着滑翔角锥 =====
      //   法向:  u_n = -g_n            （9.8 m/s^2，抵消重力）
      //   切向:  u_t = -g_t            （9.8 m/s^2，抵消重力）
      //   沿陆轴: u_r = -6*h/T^2 - 4*vz/T - g   （这才是唯一的大推力维度）
      a_cmd = u_n*conen + u_t*conet + u_r*coner
  } else {
      // ===== 无约束弧：仅在 T 足够大 / 已接近目标时可用 =====
      a_nc  = (6*r/T^2) - (4*v/T) - g*upv
      // 【安全阀】无约束弧的解必须先自检，饱和就退回约束弧贴锥
      if a_nc:mag > a_net { a_cmd = cone_arc() } else { a_cmd = a_nc }
  }

  // ---- ③ 滑翔角锥约束（G-FOLD 约束③）—— 治"横向 5.7 km"
  //   要求 水平距离 ≤ h * tan(gamma_gs)
  if dist_hz > h_aim * tan(gamma_gs) {
      cone_active = true.
  } else {
      cone_active = false.
  }

  // ---- ④ 推力指向锥（G-FOLD 约束⑦）—— 治"倾角失控"
  tilt_cmd = vang(a_cmd, upv)
  tilt_max_now = lqr_tmax_hi * (h_gnd / (h_gnd + k_taper))   // 随时间线性收紧（航空学报 Eq.14）
  if tilt_cmd > tilt_max_now { a_cmd = rotate_toward_up(a_cmd, tilt_max_now) }

  // ---- ⑤ 推力幅值显式决策（无损凸化思想）—— 治"刹停后满推力爬升"
  thr_cmd = clamp(a_cmd:mag / a_net, thr_min, 1)
```

**为什么这能同时治四个病**：
| 病 | 由哪一项治 |
|---|---|
| 缺位置约束 | ② 约束弧的 `−6h/T²` 项**就是**位置反馈，且 `T` 每帧重解 |
| 刹停后满推力爬升 | ② 约束弧在 `v→0` 时给出法向 `−g_n` ⇒ **悬停**，不是 `+a_net` 爬升 |
| 横向 5.7 km | ③ 滑翔角锥（锥面法向只需 9.8 m/s² 就能把横向"压住"） |
| 倾角不收敛 | ④ 推力指向锥 + 随高度收紧 |

**关键点**：`a_cmd` 在 `v→0` 时趋近"法向抵消重力 + 沿轴 `6h/T²`"，
**而不是**现在的 `upv·a_net`（满推力）。这正是 §2.1-B 里
`u_r^* = −6r_r/t² − 4V_r/t − g_r` 的结论 —— **常数满推力是错误的终端形式**。

### 3.3 `T` 的求根（替换 `T_burn` 冻结）

用航空学报 Eq.9（含 `v_f`，比金字塔 Eq.82 更完整），在 `v_f = 0` 时退化为：

$$g^2 t_g^4 - 4\big[(v_0{+}v_f)^2 - v_0\!\cdot\!v_f\big]t_g^2 - 24(r_0{-}r_f)\!\cdot\!(v_0{+}v_f)\,t_g - 36|r_0{-}r_f|^2 = 0$$

kOS 实现（Newton，热启动）：
```ks
// 上帧的 T_go 做初值；下限保护（Apollo 的 LEADTIME 思想）
set T_go to max(tg_min, T_go_prev).
local iter is 0.
until iter > 3 {
    set f  to ... T_go 的 4 次多项式 ...          // 用 T_go 而不是 t
    set fp to ... 导数 ...                        // 4g²t³ − 8[...]t − 24(...)
    if abs(fp) < 0.0001 { set fp to 0.0001. }     // 防除零
    set T_go to T_go - f / fp.
    if T_go < tg_min { set T_go to tg_min. }      // Apollo 的 POSMAX 保护
    if T_go > tg_max { set T_go to tg_max. }
    set iter to iter + 1.
}
```
**`tg_min = 3.0` / `tg_max = 40.0` 保留不变** —— 这正是 Apollo `LEADTIME` 防奇异的对应物。

> **与现状的差别**：`T_burn` 从"点火时算一次并冻结"变成"每帧热启动重解"。
> 日志里 `T_burn` 恒定这个"判据"要**反过来**：**新的判据是 `T_go` 应随高度单调下降且平滑**。

### 3.5 点火判据（重写）

现在的判据是**高度门**（`h_gnd < h_stop·1.3`），而 `h_stop` 用的是被低估的 `v_m`。
**正确做法**：用**能量**判据 —— "从现在开始满推力反推，是否恰好能在目标点把速度归零"。

```
// 需要的"剩余冲量能力"： (|v|²)/(2·a_net)   ← 只含速度
// 需要的"到达目标"：      h_gnd 与 dist_hz 的联合
// 点火条件：h_gnd ≤ (|v|²/(2·a_net)) · k_ign  且  dist_hz 在锥内
set v_m   to v_now:mag.                                  // 用真值，不用经验式
set h_stop to v_m*v_m / (2*max(1,a_net)).
if not ignited and h_gnd < h_stop * ign_margin {
    // 附带检查：滑翔角锥是否还能满足；不满足说明横向太远，要么早点火要么转降级
}
```
**`ign_margin=1.3` 保留**，但 `v_m` 必须换成真值 —— 用 `1.1157/0.202` 会把 917 算成 857，
**点火晚了 0.6 s（≈ 少 30 m 高度余量）**。这一项**不是本趟主因**，但是个确定的偏差。

### 3.6 降级模式（新增，必须）

// 每帧检查：从当前状态，用【最小推力】能不能到达目标上方？

## 7. 一句话给下一趟

> 现在这版的**制动能力完全够**（点火第一帧起 `need 41.5 < avail 62.14`），
> 它缺的不是推力，是**"刹停之后该干什么"**。
> 把 `v→0` 时的指令从 `upv·a_net`（满推力爬升）改成
> **"法向抵消重力 + 沿陆轴 `−6h/T² − 4vz/T`"**（贴滑翔角锥的约束弧），
> 再加上**每帧重解 T**（Apollo 在 1969 年就这么干）恢复位置约束，
> 并给 `e_tgo→0` 加一个"交班给着陆环"的出口（**永远不飞到 T=0**），这一趟就能落地。
>
> **不要再犯的错**：每换一次制导律，只闭合一部分边界条件 ——
> 缺的那一维一定会变成下一趟的失败模式（§1.3）。
> 这一次必须让**位置、速度、倾角、推力幅值**四条同时在场。
