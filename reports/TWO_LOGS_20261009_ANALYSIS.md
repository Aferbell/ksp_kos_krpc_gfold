## 3. ⚠️ 异常 A1：飞行时间 20.5~21.6 s（旧 17.5~18.4 s）

### 3.1 现象

```
  log        t_end    av_up@3s    resid3s   thr_cmd@3s
  150743     21.57       5.00       12.16      0.110     <- 改动后
  151358     20.52       5.00       14.80      0.111     <- 改动后
  175002     20.48       5.00       13.08      0.111     ★改动前★
  164053     18.16       9.59        1.28      0.127     (改动前，正常)
```

`resid3s` = `[d(vz)/dt + g0] − av_up`，即"实际净竖直加速度"减"指令值"。
新日志头 3 秒的 `resid3s` 高达 **12~15 m/s²**，而正常日志只有 ~1。

### 3.2 关键是：改动前的 `175002` 已经是同型

**`20261008_175002` 是我改动【之前】的一趟**（备份 29 之后、改动之前），
它已经具备完全相同的签名：

```
  t_end = 20.48 s        （与两趟新日志 21.57/20.52 同量级）
  av_up 头 3 秒 = 5.00   （= AVER_FLOOR 下限在托底）
  thr_cmd 头 3 秒 = 0.111（与新版 0.110/0.111 几乎相同）
  resid3s = 13.08        （与新版 12.16/14.80 同量级）
```

**⇒ A1 不是本次四项改动引入的，而是【既有的、间歇出现的】现象。**

### 3.2.1 时间线确证（决定性证据）

```
  改动生效时间： 2026/10/09 12:24（cpg_p4 .pyd 重编）+ 12:27（gfold_land.py）
  175002 日志：  2026/10/08 17:52      <- 改动前 18 小时
```

**扫全历史 38 趟**，按"早期残差"分组：

```
  resid3s > 8（强烈早期额外减速） 共 7/38 趟：
     20261001_095204   t_end=26.43  resid3s= 8.31
     20261001_105819   t_end=24.01  resid3s=12.00
     20261001_115750   t_end=43.99  resid3s=10.09
     20261007_212924   t_end=23.95  resid3s= 8.47
     20261008_175002   t_end=20.48  resid3s=13.08   (改动前)
     20261009_150743   t_end=21.57  resid3s=12.16   (改动后)
     20261009_151358   t_end=20.52  resid3s=14.80   (改动后)

  resid3s <= 3（正常）  共 26/38 趟，t_end 均值 = 19.99
  resid3s >  8          7/38 趟，      t_end 均值 = 25.85
```

**最早出现该现象的是 `20261001_095204`** —— 远早于本次改动（10/09）。

**⇒ 该现象至少从 2026-10-01 就存在，与本次四项改动无关。**
且它与"飞行时间被拉长"明确相关（两组 `t_end` 均值 19.99 vs 25.85）。


### 3.3 已验证的机理（部分）

**排除法**：锥角改动不是原因 —— 用同一交班状态分别以
新锥（35°上限+8斜率）/ 旧锥（85→5 无斜率）求解，
**`tf` 与 `plan_vz` 剖面完全相同**：

```
  锥 35+8   -> tf=18.50  peak=35.00
  锥 35 无斜率 -> tf=18.50  peak=35.00
  锥 85 无斜率 -> tf=18.50  peak=56.00
  => tf 一律 18.50，plan_vz_min 一律 -80.00
```

**力平衡**：全程 `resid_all` ≈ **−0.02**（干净），说明稳态下
`d(vz)/dt + g0 ≈ av_up` 成立。问题只在**早期约 3 秒**。

**早期额外的减速来自哪里**：用"推力竖直分量"对照实测净竖直加速度：

```
  log           tilt_act   thrust_v   a_true_net    diff    av_up
  151358 (new)      6.56      25.56       20.14     -0.95     5.00
  175002 (pre)      4.46       4.45       18.77     +4.82     5.00
  164053 (pre)      4.35      10.22       10.08     +0.12     9.59
```

- `151358`：`thrust_v`(25.56) ≈ `a_true_net`(20.14) ⇒ **额外的减速确实来自推力**
  （引擎在低油门指令下给出了远高于指令的推力）
- `175002`：`thrust_v`(4.45) 远小于 `a_true_net`(18.77) ⇒ 那时额外减速来自别处

⇒ **两趟的"早期额外减速"成因可能不同**，这一条**未能完全查清**。

### 3.4 与改动 2 的关系（需注意）

早期 `av_up` 被 `AVER_FLOOR=5.0` 托底（`av_up=5.00`），
而 `thr_cmd` 只有 0.110 —— **油门下限比例是 0.96×悬停油门**，
但此处 `thr_cmd=0.11` 对应 `av_up=5.0`，而 `g0=9.81`，
即**这个"竖直加速度"低于悬停，本应下降**，而实测却在强减速。

**这是一条独立于本次改动的既有疑点**，建议单独立项排查。

### L4 详析：为什么实飞落地 −3.68/−5.32 而不是 −2.0

离线仿真给出 −2.0，实飞给出 −3.68/−5.32。差异原因：

```
末端帧（150743）：
    t      alt      vz     av_up   av_need
  21.00   21.39  -10.38   21.64    21.64
  21.25   19.13   -7.30   21.41    21.41
  21.41   18.13   -5.47   21.32    21.32
  21.57   17.42   -3.68   19.38    19.38
```

`av_up` 已贴住 `av_need`（满刹车），说明**末段律在正确工作**。
差值来自**进场条件**：进入末段（alt=22 m）时 `vz` 已达 **−10.4 ~ −12.2**，
而离线仿真的进场速度更低。

⇒ **末段律本身没问题，是"进入末段时速度偏高"**。
这与 `plan_vz - vz` 的 p50 = **−3.32 / −3.04**（本机下降比规划慢）一致 ——
即**前段欠下降**，导致末段要补。

**建议**：下一轮把 `TERM_CLEARANCE` 或末段起始条件做成可调，
并对"进入末段时的 vz"加一条日志列，以便量化。
