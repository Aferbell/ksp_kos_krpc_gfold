### 1.3 ⚠️ 诚实说明：哪些"入场相关性"不可信


## 3. ★ 为什么 P1 消灭不了震荡（核心发现）

### 3.1 P1 限的是"二阶量"，而震荡是"一阶量"

**关键数据（`analyze_p1_binds_on_osc.py`）**：
```
  %-9s %11s %11s %11s %11s %9s
  log       a_up p50   j_max p50    震荡Δa_h   震荡半周期  震荡速率
  223120       11.72        4.90        2.31        1.93     3.22
  223914       11.77        4.30        3.13        1.54     2.52
  225956       11.65        4.20        1.12        5.41     0.21
```
最后一列"**震荡速率**" = 震荡本身需要的 `|da_h/dt|` = **0.21~3.22**，
而 `j_max` = **4.20~4.90**。

**⇒ 震荡所需的 `a_h` 变化率【始终低于】限速器的上限
⇒ P1 根本不会去限制这个震荡。**

**交叉验证**（`|da_h/dt|` 的实际分布 vs `j_max`）：
```
  log       |dah/dt|p50    p90     j_max p50   超限帧%
  223120        3.46      6.72       4.90        13%
  223914        2.44      5.99       4.30         7%
  225956        1.90      2.87       4.20         1%
```
只有 1~13% 的帧被限，**且被限的是"瞬态尖峰"，不是震荡的往复分量**。

### 3.2 机理：jerk 限制无法抑制"jerk 本来就小"的振荡

```
  P1 作用的对象：  |d(a_h)/dt| <= j_max      ← 加速度的【变化率】（二阶）
  震荡的表现形式：  倾角/姿态/速度在缓慢往复  ← 一阶量的往复
```
一个以 1.5~2.0 rad/s 往复、幅度 Δa_h≈2~3 的振荡，
其自身 `|da_h/dt| ≈ 2~3`；把它限制在 4.3 的上限下**不会改变它**。
**⇒ P1 是"防尖峰"的安全网，不是"抑制振荡"的工具。**
**我上一轮把它列为 P1 并期望它抑制震荡，这个期望本身是错的。**

### 3.3 震荡频率归属（我修正了一个重要的口径错误）

**⚠️ 我在本轮发现自己上一轮的一个口径错误**：`dist_hz` 是水平误差的**模**（≥0），
每次穿越目标就出现一个极小值，所以"两个同类极值之间的时间"其实是
**真实矢量振荡的半周期**，不是周期。

**修正后的真实周期**：
```
  log       瓣周期[s]   真实周期[s]   实测ω[rad/s]
  223120       1.93        3.86         1.63
  223914       1.54        3.09         2.04
  225956     (瓣不足)       —
  183123       1.83        3.65         1.72
  183756       2.11        4.22         1.49
```

**与两个环的带宽对照**（`analyze_att_freq.py`）：
```
  %-9s %8s %9s %11s %10s %11s %7s
  log       sched   alpha     wn_att      wn_h      实测ω    ω·dt
  223120     0.94   17.78     0.765      0.408     1.628   0.328
  223914     0.94   17.52     0.757      0.408     2.035   0.409
  225956     0.93   17.18     0.746      0.408       n/a     n/a
  （wn_att = sqrt(kp·alpha)，kp = 2.0·sched）
```
**⇒ 实测 ω（1.5~2.0）是外环 `wn_h`（0.408）的 3.7~5.0 倍，
也是姿态环 `wn_att`（0.75）的 2.0~2.7 倍。**

**⇒ 震荡频率【不属于任何单环的自然频率】。**
结合 `ω·dt = 0.33~0.41`（采样 5 Hz、每周期 7.7~18 帧），
**这更像"制导+姿态+推力延迟"合成的极限环**，
而不是某一个环的共振。

**⚠️ 我还发现并作废了一个错误结论**：我曾用 FFT 求"主周期"得到
16.8/17.25/17.68/18.60 s，惊讶地发现它"≈ 外环 `wn_h` 的周期 15.4 s"，
差点得出"外环振铃"的结论。**但检验发现：FFT 主周期 / 飞行时长 = 1.00**
（`analyze_period_vs_duration.py`）—— **那只是整段进场趋势，不是振荡。**
**该结论已作废，不引用。**

### 3.4 震荡是"制导侧 + 姿态侧"共同参与

带通方差占比（`analyze_osc_persist.py`，数值 = 该信号总方差中落在瓣频率附近的比例）：
```
  log        ah_cmd  tilt_cmd  tilt_act  att_err  avel_mag   vh   tilt_rate
  223120       0.29      0.31      0.20     0.32     0.47    0.13    0.47
  223914       0.33      0.33      0.30     0.29     0.54    0.37    0.53
  183123       0.55      0.60      0.57     0.54     0.71    0.48    0.66
```
**⇒ 指令侧（`ah_cmd`/`tilt_cmd`）、姿态侧（`tilt_act`/`att_err`/`avel`）
都在同一频率上有 0.2~0.7 的方差占比 ⇒ 是一个【闭合回路】的极限环，
而不是单一环节的噪声。**

## 4. 要不要加日志？—— **要，但补的是 3 个真空白**

我用 `audit_log_coverage.py` 对 143 列做了逐列审计（区分字符串列/缺失列/真 NaN）：

### 4.1 日志现状（143 列）

```
  ② 数值全 NaN 0 个                    —— 没有"接了但没数据"的列
```

**⇒ 覆盖度其实很好。** 但有 3 个针对本次问题**真正的空白**：

### 4.2 ★ 空白 1（最重要）：**偏航 PID 三项完全没记录**

**点名检查结果**：
```
    pid_px   俯仰 P 项    n=223 std=0.116      <- 有
    pid_dx   俯仰 D 项    n=223 std=0.2315     <- 有
    pid_ix   俯仰 I 项    n=223 std=0        <- 有（恒 0）
    pid_pz   偏航 P 项    *** 列不存在 ***
    pid_dz   偏航 D 项    *** 列不存在 ***
    pid_iz   偏航 I 项    *** 列不存在 ***
```
源码核对：`gfold_land.py` 里
```python
self.dbg_pid_px = float(-err_x * _kp_x)
self.dbg_pid_dx = float(-self.ctrl_x_rot.diff * CTRL_X_ROT_KD)
self.dbg_pid_ix = float(-self.ctrl_x_rot.integral)
```
**只有 `_x`（俯仰）被记录，`_z`（偏航）三项从未定义、也从未进 `COLS`。**

**为什么这是本次最大的空白**：
- 偏航饱和 `satZ` 达 **20~33%**，而俯仰 `satX` **恒为 0**
  ⇒ **饱和【全部】集中在偏航**，而偏航的 PID 分解却看不见。
- 我上一轮只能看到 `pid_out_z` 饱和到 ±1，**无法判断是 P 太大、D 失效、还是误差本身太大**
  ⇒ 无法对症下药。

**⇒ 建议加的列**：`pid_pz`、`pid_dz`、`pid_iz`
（在 L3067-3069 旁镜像三行，并在 `COLS` ④ 段与 `_dbg_cols` 注册）。
**成本**：约 6 行代码、3 列日志。

### 4.3 空白 2：**姿态环的"微分/速率"通道不可见**

现有 `rate_x`/`rate_y` 是**馈入 PID 的角速度项**，但缺：
- **`tilt_cmd` 的一阶差分**（= 指令角速率，实测 p50 只有 8~11 deg/s，
  但 p90 到 22~25 ⇒ 想看尖峰时它有多快）
- **参考方向的实际转动速率**（`ref_slew` 有，但它是"允许值"还是"实际值"？
  核对源码：`dbg_ref_slew` 在**未被限**时记的是实际速率、**被限**时记的是允许速率 —— 口径混用）
- **`tilt_act` 的一阶差分**（与 `tilt_rate` 不同：`tilt_rate` 用的是 `game_dt`，
  而 `game_dt` 曾经有过标度错误的历史）

**⇒ 建议加**：`tilt_cmd_rate`、`tilt_act_rate`（都用 `loop_dt` 而非 `game_dt`）。
理由：**姿态环的相位滞后是我唯一还没能量准的量**，
而它决定了"是加阻尼还是降指令速率"。

### 4.4 空白 3：**FIN 段 68 列冻结**（已知问题，但本次暴露了新后果）

实测（223914，FIN 段 9 帧）：
```
    hd_n  std=0        hd_e  std=0
    he_n  std=1.1e-16  he_e  std=0
    dp_n  std=1.1e-16  dp_e  std=0
    dve_n std=0        dve_e std=0
```
**FIN 段里这些列全部冻结**（因为它们由 gfold 律计算，FIN 不走那条路）。

**新后果（本次发现）**：落地偏差有相当一部分**是在 FIN 段形成的**：
```
  %-8s gfold末dist  FIN末dist  FIN内Δdist
  223120      25.29      19.28      -6.01    <- FIN 改善了 6 m
  223914       5.43       3.84      -1.59
  225956       2.81       8.21      +5.40    <- FIN 反而变差 5.4 m
  183756       5.65      18.73     +13.08    <- FIN 恶化 13 m
  183123      12.76       1.18     -11.58    <- FIN 改善 11.6 m
```
**⇒ FIN 段既能纠正 11.6 m，也能恶化 13.1 m。**
**但 FIN 段的误差量（`he_*`/`dp_*`）是冻结的 ⇒ 无法诊断 FIN 为什么变差。**
（`fin_a_up`/`fin_need`/`fin_ah` 三列是 FIN 自己的量，有记录 —— 但缺少
"FIN 用的水平误差从哪来"。）

**⇒ 建议**：FIN 段改为直接用**实时** `error`/`vel` 计算并记录
`fin_dp_n`/`fin_dp_e`/`fin_dve_n`/`fin_dve_e`（4 列），
或至少把 `fin_on=1` 时 `dp_*`/`dve_*` 保持更新。

| **E2** | 临时把 `CTRL_X_ROT_KP`/`KD` 各变 ±50% 飞两次 | 姿态环是否限环（ω 是否随增益移动） |
| **E3** | 临时把外环 `T` 固定为 8（而非 6）飞一次 | 外环是否参与（ω 是否随 T 移动） |
| **E4** | 只加 §4.2 的偏航三项，飞一次 | 偏航饱和的构成（P/D/误差 谁主导） |

**E2/E3 是"频率是否随参数移动"的经典判别法**：
若改变 `KP` 后 ω 跟着变 ⇒ 姿态环主导；若改变 `T` 后 ω 跟着变 ⇒ 外环主导；
若都不变 ⇒ 是延迟/采样决定的极限环（那就该减延迟或降采样相关增益）。

**另外**：`223120` 落地 19.28 m（最差），而它的 `dist0=71.8` 与 `E斜率=−0.037`（衰减）
⇒ **它的差不是"震荡发散"造成的，而是"进场就有 71.8 m 水平偏差 +
FIN 段只纠正了 6 m"**。**这说明"减少接手时的水平偏差"（kOS 侧）
可能比"抑制震荡"对落点更有效。**
