## 2. 【新发现】水平极限环：根因是**方位角**，不是倾角

### 2.1 现象

```
dist:  min=0.42  max=29.17   p50=4.49
vh:    p50=3.79  p90=8.77    max=9.66
水平误差显著极值时刻: t=4.7 / 9.5 / 13.7 / 18.0
半周期 4.2~4.8 s  =>  周期 ~8.6 s（omega=0.73 rad/s）
```

外环线性闭环周期 `2*pi/wn = 2*pi/0.408 = 15.4 s`，而观测振荡周期只有 **8.6 s**
⇒ **不是外环线性失稳**，另有机制。

### 2.2 根因：载具在**绕目标点公转**

**直接证据（来自真日志，无须建模）**：

```
指令方位角累计转过   798 deg  (2.2 圈)   <- tgt_az
机头方位角累计转过   926 deg  (2.6 圈)   <- nose_az
载具位置角累计转过   566 deg  (1.6 圈)   <- ORBITING
|az_err| (机头 vs 指令方位)  p50=39.3 deg   max=161.8
    >30 deg: 56/93 (60%)
    >90 deg: 36/93 (39%)
```

**机制（自激环）**：

```
载具公转 -> 误差矢量跟着旋转 -> 指令方位角旋转
        -> 机头转不过来（滞后 39~90 deg）
        -> 推力带切向分量 -> 切向分量维持公转  <= 闭环自激
```

**推力浪费量化**：

```
鼻锥方向的切向分量占比   p50=0.25   p90=0.81
径向（指向目标）分量     p50=0.96
径向 < 0（推离目标！）   29/93 帧 (31%)
```

### 2.3 为什么此前没发现

上一轮的全部注意力都在**倾角**（`tilt_act` vs `tilt_cmd`）。本趟实测：

| 通道 | 误差 p50 | max |
|---|---|---|
| 倾角 | **7.6°** | 27.4° |
| **方位角** | **39.3°** | **161.8°** |

**方位角误差是倾角误差的 5 倍**。`az_err` 这一列一直存在，
但此前从未被判读过——**这是本次分析最有价值的发现**。

### 2.4 建议修复方向（**未实现，需先离线验证**）

| 候选 | 做法 | 依据 |
|---|---|---|
| **F1 方位角速率限制** | 给指令方位角加 slew 上限（倾角通道有，方位角**没有**） | `d(tgt_az)/dt` p90=120、**max=851 deg/s**（= 每秒 2.4 圈），物理不可能 |
| **F2 径向优先** | `a_h` 只用误差的**径向**分量，切向置零 | 直接消灭"切向推力维持公转" |
| **F3 公转抑制** | 误差矢量旋转时降低增益（相位超前） | 切断自激环 |

**诊断脚本已就绪**：`dev/test_azimuth_fix.py`。
**但注意**：我写的简化模型**有 bug（数值发散到 1e9）**，
修好之前**不要采信它的任何结论**（详见 §7）。

### 2.5 ⚠️ 一条被推翻的假设

我最初以为是 `T_GAIN_MIN=6` 夹得太紧（**77% 的帧** `T` 被下限夹住，
使外环比自然时标慢 2.3 倍）导致外环失稳。**离线扫参推翻了它**：

```
Tmin   land_vz  dist_end   dist_rms
 2.0     -2.01     1.95      9.58
 4.0     -2.01     0.23      9.52     <- 更好
 6.0     -2.01     1.88      9.65     <- 实飞
10.0     -2.03     7.78     11.07
14.0     -2.04    12.82     12.78
```

**减小 T 反而更好**，且基线的 `dist_end` 已是 0.5~2 m。
⇒ **外环增益不是瓶颈**，不要去调 `T_GAIN_MIN`。

## 4. 姿态环：权限够，但存在**结构性滞后**

```
tilt_act-tilt_cmd   p50=-0.42  p90=+18.72  max|.|=27.42 deg
att_err             p50=13.75  max=34.25 deg
d(tilt_cmd)/dt      p50=0.5(abs 7.3)  p90=16.2  max=27.0 deg/s
corr(tilt_err, d(tilt_cmd)/dt) = -0.308   (负 => 指令超前 = 滞后)
alpha_max           p50=14.56  p10=10.04  max=30.09 deg/s^2
avel_mag            p50=9.71   max=18.56 deg/s
tilt_rate           max=17.20 deg/s
```

**权限充足性（正确口径）**：

```
所需 alpha = amp*w^2 = 13.9 deg * (0.733 rad/s)^2 = 7.44 deg/s^2
实测 alpha_max p50 = 14.56  =>  够（2 倍余量）
物理允许 slew = sqrt(2*alpha*45deg) = p50 36.2 deg/s
实际达到 slew = 17.2 deg/s   =>  只用到物理极限的 47%
```

**⇒ 姿态不是权限受限，而是"跟踪滞后"**：
实际角速率只发挥到物理极限的一半，说明 **PID 增益偏低**
（`CTRL_X_ROT_KD=4.0` 已由用户从 2.5 调高）。

**`pid_sat_z`（偏航轴饱和）12% 的帧**，而 `pid_sat_x`（俯仰）**0%**
⇒ **饱和集中在偏航轴**，与 §2 的方位角问题**同源**（偏航负责航向）。

**这一条独立佐证了 §2 的结论**：瓶颈在航向（偏航），不在俯仰（倾角）。

## 5. 落地偏硬：`vz=-6.64` vs 设计目标 2.0

```
末 5 帧:  -16.17  -13.83  -11.37  -8.40  -6.64
plan_vz:  -5.01
av_need 在最后两帧: 31.31 -> 49.89  (slack 15.7 -> 19.3)
```

**原因**：`av_need = g + (vz² − 2²)/(2h)`，当 `h→0` 时该上界**爆炸**
（`h=0.26 m` 时 need=86.9，而 `a_cap`≈57）⇒ **上界失效，不再约束**。
载具在高度耗尽前没来得及把 `vz` 从 -18 刹到 -2。

**⇒ 可优化点**：末段需要一个**不依赖 h 的**减速保证，例如：
- 用 `av_plan`（规划自己的竖直剖面）而非 `av_need` 作为末段主导
  —— 规划 `plan_vz` 末节点是 -5.01，比实际 -6.64 好
- 或在 `h < TILT_TERM_ALT` 时切换到"按剩余时间"的减速律

**注意**：`-6.64 m/s` 仍在着陆腿承受范围内（本次未损坏），
故这是**优化项，不是缺陷**。

## 6. 本轮修的 2 个日志列 bug（只影响日志，不影响控制）

对 138 列做了"恒空/恒定"扫描，发现 **2 列为 ALL EMPTY**：

| 列 | 原因 | 修法 |
|---|---|---|
| `ctrl_ms` | 我在 `__init__` 声明了 `dbg_ctrl_ms`，但**原样沿用的 `run()`** 写的是 `dbg_seg_ctrl`（旧名）⇒ 读取恒空 | `_dbg_cols` 改读 `dbg_seg_ctrl`，并删掉错名声明 |
| `tf_tgo` | 该列由 `_tgo` 计算块产出，而该块**只喂诊断**、已在重写中删除 ⇒ 永远无人写 | 删掉该列（剩余时间用 `run()` 已有的 `tgo` 列，重复无益） |

**验证**：`Logger.COLS` 139 → 138，`check_cols_krpc` PASS，
pyflakes/check_names/check_krpc_api 全 PASS。

**这是"重写 `__init__` + 原样沿用 `run()`"这类改动的典型风险**：
属性名在两处不一致，静态检查查不出。已写入 `dev/audit_attrs.py` 的价值说明。

其余恒定列（`replan_n=1`、`solve_ms`、`tf=18.5`、`vdesc=80`、
`draw_on=1` 等）都是**单次飞行内的正常恒定**，不是 bug。
