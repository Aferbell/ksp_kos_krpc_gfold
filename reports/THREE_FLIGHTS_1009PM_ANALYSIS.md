## 2. ★解答长期疑点：`TARGET_ALT=17` 高约 2.5 m

三次 `LANDED` 时的高度：

| 日志 | LANDED alt | 与 TARGET_ALT=17 差 |
|---|---|---|
| 213600 | 14.40 | **−2.60 m** |
| 214641 | 14.10 | **−2.90 m** |
| 215317 | 15.07 | **−1.93 m** |
| **平均** | **14.52** | **−2.48 m** |

**⇒ KSP 的 `situation == 'landed'` 在 `alt ≈ 14.1~15.1 m` 触发，
而 `TARGET_ALT = 17`。**

这**同时解释**了三件事：

1. **上轮遗留的「日志 alt 与视频仪表盘末秒差 ~7.7 m」疑点** ——
   部分来自这个常数偏差 + 时序。
2. **视频观测「引擎熄灭后载具仍下沉约 2 m、历时约 0.8 s」** ——
   就是这 2.5 m。
3. **为什么旧行为（撒手）会导致猛烈撞击** —— 旧行为在 `alt<=18` 撒手，
   而真实触地在 14.5 m，中间有 **3.5 m** 无人控制；
   现在 FIN 正好覆盖了这段「规划没覆盖」的高度。

**术语纠正**：下文中「触地」指 `situation==landed`；
`TARGET_ALT=17` 实际是**规划的零速点基准**，不是腿触点。

### 2.1 为什么这个疑点以前看不见（FIN 的附带价值）

**旧行为下这个偏差是"不可观测"的**：旧代码在 `alt<=18` 就 `break` 并退出，
日志**最后一行永远是 alt≈17.3~17.9**（如 150743 末帧 17.42、151358 末帧 17.89），
**真实触地过程根本没有被记录**。

现在 FIN 段持续控制并记录到 `situation=='landed'`，
日志才第一次显示出真实触点（14.10~15.07）。

**⇒ 这解释了为什么上轮我把「日志 alt 与视频差 ~2 m」列为未解疑点 ——
不是数据错，而是旧代码根本没记录到触地。FIN 顺带解决了这个疑点。**

## 3. ⚠️ 发现的真实回归：落点精度变差

### 3.1 现象

| 日志 | land_dist | 批次 |
|---|---|---|
| **213600** | **19.31 m** | 新 |
| 214641 | 4.09 m | 新 |
| **215317** | **31.68 m** | 新 |
| 154838 | 1.46 m | 改动前 |
| 160001 | 6.12 m | 改动前 |
| 150743 | 4.92 m | 改动前 |
| 151358 | 3.22 m | 改动前 |

### 3.2 机理：**"先到目标、横速未消、冲过去"**

以 `213600` 为例：

```
t=11.50   dist= 0.84 m   vh=13.25   <- 位置到了目标，但横速还有 13.25 m/s
t=12.81   dist=18.49 m   vh=10.09   <- 冲过去了
t=14.11   dist=24.60 m   vh= 0.64   <- 横速终于消掉，但已在 24 m 外
t=16.45   dist=19.31 m             <- 落地
```

`min_dist` 时刻的横速（越小越"停得住"）：

| 日志 | min_dist | **vh@min_dist** | 之后剩余时间 |
|---|---|---|---|
| 213600 | 0.84 | **13.25** | 4.95 s |
| 214641 | 0.11 | 5.99 | 7.78 s |
| 215317 | 0.50 | **0.17** | 6.68 s |
| 154838 | 1.11 | **14.78** | 11.91 s |
| 150743 | 0.41 | 4.50 | 10.08 s |

**两趟新日志（213600/215317）"到达时横速大 + 之后剩余时间只有 5~7 s"**，
而改动前是 10~16 s —— **时间不够拉回来**。

### 3.3 根因：`AIM_ALT=500` 把可用时间**减半**

```
              交班高度    tf(规划)   实飞总时长
新三趟         651~655 m   12.8~14.0 s   16.5~20.2 s
改动前四趟    1133~1151 m  18.0~25.0 s   20.5~25.4 s
```

**可用竖直距离与时间几乎减半**，而入场横速并未变小：

| 日志 | vh@gate | 说明 |
|---|---|---|
| 213600 | 13.5 | 正常 |
| **214641** | **29.8** | ★ 远超 kOS 的 `vh_gate=10` |
| **215317** | **26.3** | ★ 远超 kOS 的 `vh_gate=10` |

**⚠️ 这正是当初否决 `aim_alt=500` 的理由（kOS 第 238~248 行的记录）。**
我在上轮报告 §2.4 把它标为「风险未消除」，**现在它兑现了**。

### 3.4 但要说清：**穿越目标本身是既有现象**

```
              min_dist   穿越次数(改动前也有)
213600          0.84         3
214641          0.11         4
215317          0.50         2
154838          1.11         2
160001          0.44         4
150743          0.41         4
151358          0.31         4
```

`vh` 振荡周期新三趟 4.9 / 2.6 / 7.7 s，改动前 4.0 / 4.8 / 3.7 / 4.6 s
—— **同量级，不是新引入的极限环**。

**⇒ 真实结论：水平通道的"穿越-漂回"是既有的；
`AIM_ALT=500` 缩短了可用时间，使既有的穿越来不及收回 → 落点变差。**

### 3.5 ★归因：是 AIM_ALT（时间），不是入场横速

我起初怀疑是"入场横速更大"导致的，**但数据否定了这个解释**。
用 7 趟做相关性（`verify_accuracy_cause.py`）：

```
corr(land_dist, alt@gate) = -0.685   <- 交班越高，落点越准
corr(land_dist, vh@gate)  = -0.038   <- 与入场横速【几乎无关】
corr(land_dist, t_end)    = -0.442
corr(land_dist, vz@gate)  = -0.251
```

**控制 vh 后的分组比较**（关键）：

```
--- vh < 16（同区间）---
  213600  new  alt= 663.6  vh=13.1  land_dist=19.31
  160001  pre  alt=1165.6  vh=15.3  land_dist= 6.12
  150743  pre  alt=1156.3  vh=14.0  land_dist= 4.92
  151358  pre  alt=1163.7  vh=11.9  land_dist= 3.22
  => new 均值 19.31 (n=1)  vs  pre 均值 4.75 (n=3)
```

**在相同横速区间内，交班高度低的那一趟落点差 4 倍。**
⇒ **归因于 `AIM_ALT=500`（可用时间减半），入场横速不是主因。**

离线 A/B（同一交班状态，只改 `AIM_ALT`）也一致支持：

```
  case      AIM   handAlt  land_dist
  213600    500     667       0.17
  213600   1000    1167       2.52
  214641    500     667       4.47
  214641   1000    1167       0.08
  215317    500     667       1.46
  215317   1000    1167       0.03
```

**⇒ 倾向归因于 `AIM_ALT=500`（可用时间减半），但证据强度有限（见 §7 诚实说明）。**

### 3.6 闭环仿真：不一致，说明还有别的因素

用同一交班状态做闭环（含 FIN），只改 `AIM_ALT`：

```
  case      AIM   handAlt  land_dist
  213600    500     667       0.17     <- 500 更准
  213600   1000    1167       2.52
  214641    500     667       4.47     <- 1000 更准
  214641   1000    1167       0.08
  215317    500     667       1.46     <- 1000 更准
  215317   1000    1167       0.03
  均值      500 -> 2.03        1000 -> 0.88
```

**⇒ 仿真里 `AIM_ALT=1000` 平均更准（0.88 vs 2.03 m），但并非每趟都更好**
（213600 反而 500 更准）。且仿真落点 0.03~4.47 m **远好于实飞 19~32 m**。

差异来自仿真没有的东西：**姿态动力学滞后**
（`att_err` p90 = 19~31 deg、`tilt_rate` 峰值 13~31 deg/s）。
仿真里 `a_h` 立即生效，实飞要先把箭体转过去。
**说明问题不在控制律本身，而在"实飞姿态跟不上 + 时间紧"的组合。**

### 3.7 ★落点误差主要在 FIN **之前**就已形成

分开看 FIN 入口与终点的 `dist`：

```
  log      dist@FIN入口  dist@触地   变化     vh@FIN  vh@触地
  213600       23.82       19.31    -4.51     2.22    2.61
  214641        0.16        4.09    +3.93     3.95    0.70
  215317       23.17       31.68    +8.51     5.49    3.17
```

- **213600 / 215317 在进入 FIN 时就已经偏了 23 m** ——
  落点误差的**主体在 FIN 之前**（即 gfold 水平跟踪段）就已形成。
- 214641 进 FIN 时几乎正中（0.16 m），FIN 期间漂到 4.09 m。
- 215317 在 FIN 期间向外漂了 8.5 m、用时 1.86 s ——
  与"以约 4.6 m/s 平均横速自由漂移"的量级一致（4.6×1.86≈8.6），
  **说明 FIN 在这 3 m / 1.9 s 内对水平通道的纠正能力很有限**
  （它把 vz 与姿态放在优先位置，这是设计取舍）。

**⇒ 结论：落点精度问题的主体在 gfold 水平跟踪段，而非 FIN 段。
FIN 不为此负责（它的任务是软着陆 + 姿态）。**
**但这同时说明：仅靠调 FIN 无法改善落点精度。**

### 关于建议 4 的谨慎说明

`TARGET_ALT=17` 虽然比真实触点高 2.5 m，但**改它牵动面很大**：
规划零速点、`TERM_CLEARANCE`、`FIN_ALT`、kOS 侧 `target_alt`、以及
"KSP 何时报 landed"的不确定性。**本次 FIN 已经很好地兜住了这 2.5 m**，
所以**不建议现在改**，只记录事实。

### 关于建议 1 的两难

`AIM_ALT=500` 也让 **P1/P3 更安全**（时间短 ⇒ 低推力段更短；
FIN 覆盖更充分）。回调到 700~1000 会：
- ✅ 恢复落点精度
- ❌ 让低推力段变长（P1 的问题回归）
- ❌ 增加暴露时间

**折中建议：`AIM_ALT=700`**（交班 867 m，时间约为 500 的 1.3 倍，
仍比 1000 短）。需实飞验证。

## 7. 诚实说明

1. **P1/P3 的效果已确证**（P3 完全达标，三次撞击垂速 −1.97~−2.04；
   P1 有实飞 + 离线 A/B 双重证据）。
2. **P2 带来落点回归**：现象确凿（19.31 / 31.68 m vs 改动前 1.46~6.12 m），
   但**归因证据强度只是"倾向"**，理由：
   - 实飞样本只有 **3 趟新 + 4 趟旧**，n 太小；
   - `vh<16` 分组里新批次只有 **1 趟**（213600），无法排除偶发；
   - 离线 A/B 里 `AIM=1000` **并非每趟都更准**（213600 反而 500 更准），
     均值 0.88 vs 2.03 m 的差距不算决定性；
   - **缺"只改 AIM_ALT 而其他不变"的实飞对照**。
   ⇒ 我把它记为**强相关 + 有机理支撑（时间减半）**，
     而**不是已证因果**。建议用一次实飞对照来定论。
3. **水平"穿越-漂回"现象是既有的**（改动前四趟同样穿越 2~4 次，
   `vh` 振荡周期同量级）。我把它与"落点变差"区分开，
   避免误判为本次引入。
4. **`TARGET_ALT` 高 2.5 m 的结论基于 3 次样本**，且三次相当一致
   （14.10 / 14.40 / 15.07），但**仍建议继续观察确认**。
5. **`vdesc` 日志列读数是常量**（记的是 `V_DESCENT_MAX_ENABLE`，
   不是实际生效的 `vc`）。本次 S2 的有效性只能靠离线 A/B 验证，
   **这是一个日志缺陷**，建议修（见 §6 建议 2）。
6. 本轮**未改任何飞行代码**。
