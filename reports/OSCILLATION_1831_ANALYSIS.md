（下降更陡）⇒ 通过代码里**固有的耦合** `a_h_max = a_up·tan(cap)`
把竖直的"余量"直接转换成了水平的"过快指令"。**

### 4.3 相位法失败（诚实记录）

### 6.1 关于 P1 的具体形式

链条是 `a_h_max` 翻倍 → 外环敢给快指令 → 姿态跟不上。
**两种切入方式**：

- **(a) 限指令速率**：对 `tilt_cmd`/`tgt_az` 的变化率加上限。
  **我核对代码确认：`tgt_az` 完全没有限速** ——
  `gfold_land.py:1784-1786`：
  ```python
  _az = self.tf_az_dir
  if _ah_dem > 1e-09 and _perr > TILT_AZ_MIN_ERR:   # 只有"冻结"门，没有速率限制
      _az = (_ah_vec / _ah_dem).copy()
      self.tf_az_dir = _az
  ```
  即方位角**直接取自合矢量**，唯一的保护是"`|dp|` 小时冻结"。
  这是 HANDOFF §6.4 早已记录的缺口，本次数据给了它新的紧迫性
  （p90 达 **116 deg/s**，而可达 slew ≈ 40 deg/s）。

- **(b) 限 `a_h` 变化率**：内环（措施2）已在限 `|da_h/dt| ≤ j_max`，
  **但我实测它形同虚设**：
  ```
    log      ah_cap_bind=1   |j_used|/j_max p50   p90    >0.9 占比
    183123        0%              0.199         0.463      2%
    183756        0%              0.259         0.587      3%
    124409        2%              0.135         0.436      7%
  ```
  **⇒ `j_max` 给得太松（`j_used/j_max` 中位仅 0.2），从未起到约束作用。**
  把 `j_max` 与姿态可达 slew 挂钩（而不是与 `alpha·headroom` 挂钩）会更有效。

**⇒ 建议 (b) 优先**（既有机制，只需把 `j_max` 收紧到有约束力），
**(a) 补齐 `tgt_az` 的限速**（代码里确实完全没有）。
