## 1. 倾角是怎么失控的

### 1.1 形态：不是"过冲振荡"，是**"指令退、机身不退"的失速**

关键窗口 `t=13.6~16.2`（`diag26` 第[3]段）：

| t | tilt_cmd | tilt_act | rate_cmd | rate_act | slew_allow |
|---|---|---|---|---|---|
| 13.83 | 30.88 | 18.43 | +9.45 | +9.80 | 10.03 |
| 14.24 | 34.76 | 28.23 | +9.11 | **+28.46** | 9.66 |
| 14.43 | 35.00 | 34.40 | +1.24 | **+31.80** | 9.31 |
| 14.60 | **35.00** | 39.66 | **0.00** | **+30.23** | 9.75 |
| 15.15 | 29.77 | 52.12 | **-9.85** | **+20.30** | 9.89 |
| 15.77 | 25.81 | **57.37** | +1.08 | +3.04 | 10.00 |

**指令在 14.43 就停在 35 deg（cap 上限）不动了，而机身还在以 30 deg/s 继续转。**
指令随后开始下降（-9.8 deg/s），机身却继续冲到 **57.37 deg**。

```
|rate_act|  p50=10.05  p90=26.19  max=43.86 deg/s
slew_allow  p50= 6.76  max=11.55 deg/s
|rate_act| > slew_allow 的帧 : 64/90 = 71.1%
```

⇒ **机身转动速度是指令限速上限的 1.5~4 倍。过冲来自已积累的角动量，
不是"指令要得太快"。**

### 1.2 相位回归仍指向滞后，但**这次出现了真正的过冲成分**

```
reg (tilt_act - tilt_cmd) = -0.8979 * d(tilt_cmd)/dt   corr = -0.548
  指令减小帧 平均(ta-tc) = +13.60 deg  (n=39)   <- 滞后
  指令增大帧 平均(ta-tc) =  -2.63 deg  (n=48)   <- 滞后
```

倾角通道**主要是滞后**（`tau_att ≈ 0.90 s`）。
但同时：

```
tilt_act > TILT_CAP_HI=35 的帧 : 26/91
tilt_act > 45 deg（深度失控）  :  8/91
tilt_act 局部极大: t=5.29(31.3) t=11.05(43.1) t=15.77(57.4)
  峰间隔 5.77 / 4.72 s，且【峰值逐次升高】31.3 -> 43.1 -> 57.4
```

**峰值单调升高 = 净阻尼为负**，这是**真过冲**（上一趟没有这么明显）。
两趟的差别：本趟 `tilt_cmd` 在 14.4~16.2 长时间**贴在 cap=35 不动**
（OLD 趟没有这么长的饱和平台）—— 饱和平台让积分型角动量持续积累。

### 1.3 根因：**级联带宽失配**（这是本次最硬的发现）

内环（姿态）带宽 vs 外环（水平制导）带宽：

```
wn_att = sqrt(alpha * kp_att)     p50 = 0.608 rad/s
wn_h   = sqrt(6/T^2) (T=CA_T_MIN=4) p50 = 0.612 rad/s
带宽比 wn_att / wn_h = 0.99
```

**级联设计准则要求内环比外环快 3~5 倍，实测是 1.0 倍。**

即：**姿态环与外环同带宽** —— 外环下达指令时，姿态环还在自己振荡，
外环无法把姿态当作"快速跟随环节"。这正是"指令退、机身不退"的结构性原因。

更糟的是姿态环本身欠阻尼：

```
zeta_att = (KD*RATE_D_GAIN/2)*sqrt(alpha/kp_att)  p50 = 0.366
```

### 1.4 用**真实 2 阶姿态动力学**重算相位裕度：**PM 仍为负**

HANDOFF §4.3 用 **1 阶 tau=1.31 s** 模型算出 `CA_T_MIN=4 -> PM=+18.7 deg`。
但实测 `zeta_att=0.366 < 1`，姿态环是**欠阻尼 2 阶**，用 1 阶模型会**高估**裕度。

> **⚠️ 更正说明**：本节最初（`diag25`）算得 `-78.5 deg`，那个数字**是错的** ——
> 我的 2 阶幅值函数漏了分子 `wn^2`（`|G_att|=wn^2/hypot(wn^2-w^2, 2 z wn w)`），
> 使 `|L|` 被低估、`wc` 偏高、PM 偏负。已在 `diag28_pm_corrected.py` 修正。
> 修正后做了**两个可独立验证的自检**：
> - 自检A：1 阶口径复现 HANDOFF 的 **+18.72 / +36.73**（对 +18.7/+36.7）✅
> - 自检B：令 `wn->inf`（姿态理想）应趋于纯双积分器 `(kp+kv s)/s^2`，
>   解析值 **+70.53 deg**，数值计算 **+70.53** ✅
>
> 下表为**修正后**数值。

  ⇒ **PM = -65.1 deg**。

### 1.5 完整因果链

```

## 2. 第二步能不能改善？

### 2.1 第二步改的是外环增益，**不碰姿态环**

```

```

它**不改**：`alpha_max`（姿态权限）、`CTRL_X_ROT_KP/KD`（姿态增益）、
`tf_slew_allow`（倾角限速器）。
它只**间接**影响 `_ca_kp -> _ah_vec -> _tcorr -> tilt_cmd`，
即"让外环别要得那么急"，**不是"提高姿态跟踪能力"**。

### 2.5 第二步的**方向**对相位裕度有利，但与末段需求冲突

```

⇒ 抬 `T` 确实改善外环相位裕度（**这是第二步唯一真正的理论收益**）。
**但** `T` 越大外环越慢 → 末段越跟不上 `vh` 增长，
而末段已有 **12 帧物理不可能**，抬 `T` 只会更糟。

**两者不可兼得** ⇒ 第二步必须与"提高姿态权限/降低末段 vh"一起做。

### 2.6 若目标是治倾角失控，正确的方向是（修正后的旋钮扫描）

`diag28_pm_corrected.py` 扫了三个旋钮（基准 `wn_att=0.608`、`zeta=0.366`）：

| 优先级 | 措施 | 依据 |

> 姿态环符号极敏感 —— 必须**单独一趟验证**，不要与其它改动混做。

## 3. 一句话总结

- **倾角失控 = 级联带宽失配（内环/外环 = 0.99，应 3~5）+ 姿态环欠阻尼
  （zeta=0.37）+ `tilt_cmd` 在 cap=35 长时间饱和** ⇒ 净阻尼为负、
  过冲逐次升高（31→43→57 deg）、`a_h` 实际达指令 1.7 倍、被推飞。
  修正后的外环相位裕度 `PM(T=4) = -65.1 deg`（临界 T=10.79 s，
  整个 `[4,8]` 窗口 PM 都为负）。
- **第二步治不了它**：失控窗口的 T 本来就可行的（15 帧只改 2 帧），
  而它能改的帧有 57% 物理不可能，按原文实现还会让 100% 的帧增益减半。
  第二步唯一真实收益是抬 T 改善外环 PM，但这与末段需求直接冲突。
- **下一刀应砍"姿态权限（`alpha_max`）+ 姿态阻尼（`KD`）"与倾角饱和平台**，
  不是 T。单靠 `KD` 无法把 PM 转正（提到 8.0 仍 -29.7 deg），
  必须**同时**提高内环带宽。
