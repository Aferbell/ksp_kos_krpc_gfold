## 1. 先把「力气不够」这个假设排除

新旧载具的**姿态角加速度几乎相同**：

| 趟 | 质量 t | 推力 MN | a_cap | **I_p** | tau_p | **alpha** |
|---|---|---|---|---|---|---|
| 旧 164053 | 153.5 | 1.67 | 10.85 | 1.44e7 | 3.53e6 | **13.9** |
| 旧 124409 | 149.4 | 1.45 | 9.72 | 1.43e7 | 3.74e6 | **15.0** |
| 旧 143917 | 149.0 | 2.33 | 15.60 | 1.45e7 | 4.76e6 | **18.6** |
| 新 144058 | 963.6 | 13.70 | 14.21 | **4.11e8** | **1.17e8** | **16.1** |
| 新 154351 | 967.6 | 14.38 | 14.86 | **4.12e8** | **1.20e8** | **16.4** |

`alpha` 新旧都在 14~19 deg/s²。转动惯量涨了 **28 倍**（1.44e7 → 4.11e8），
但引擎数 9→13、万向节力矩同步涨了 **33 倍**（3.5e6 → 1.17e8），正好抵消。

**⇒ 「新载具姿态力气不够」是错的。真正差的是「同样的 alpha 下，转动惯量大 28 倍意味着同样的 omega 蕴含 28 倍角动量」。**

## 2. 核心判据：峰值角速率能不能刹住

```
需要 alpha = omega^2 / (2 * headroom)      headroom = 45 deg
可用 alpha = alpha_max（实测）
```

| 趟 | omega 峰值 | alpha 可用 | alpha 需求 | 余量 | 判定 |
|---|---|---|---|---|---|
| 旧 164053 | 0.138 | 13.9 | 0.7 | **20.08×** | 刹得住 |
| 旧 124409 | 0.043 | 15.0 | 0.1 | **222.85×** | 刹得住 |
| 旧 143917 | 0.350 | 18.6 | 4.5 | **4.16×** | 刹得住 |
| **新 144058** | **0.959** | 16.1 | 33.5 | **0.48×** | **刹不住** |
| **新 154351** | **0.794** | 16.4 | 23.0 | **0.71×** | **刹不住** |

换算成「需要几个控制周期才能刹住」：

```
L = I * omega            刹住时间 = L / tau
旧 124409: L=6.2e5 Nms, tau=3.7e6  =>  0.16 s  ( 1.6 帧)
旧 183756: L=1.2e6 Nms, tau=4.3e6  =>  0.28 s  ( 1.4 帧)
新 154351: L=3.3e8 Nms, tau=1.2e8  =>  2.72 s  (12.4 帧)   <-- 慢 10 倍
```

zeta_eff = (1/omega_peak)/2 * sqrt(alpha/kp)    （D 被 clamp 到 1 后反解的实际值）

## 4. 旧程序为什么没出现这个问题（关键）

### 4.1 旧程序**有完全相同的 bug**，而且记录在案

`dev/reports/FLIGHT_20261008_ANALYSIS.md:52` 的标题就是「**新发现：水平极限环，根因是方位角**」：

```
旧 164053: 载具绕目标 1.6 圈 / 指令方位 2.2 圈 / 机头 2.6 圈
           |az_err| p50=39.3°  max=161.8°   39% 时间 >90°
           偏航轴饱和 11.8%
```

和新载具几乎一模一样：

| | 旧 164053 | 新 154351 |
|---|---|---|
| 绕目标 | 1.19 圈 | **1.21 圈** |
| 指令方位 | 2.22 圈 | 1.58 圈 |
| 机头方位 | 2.57 圈 | 2.13 圈 |
| az_err p50 | 39.3° | 59.5° |

### 4.2 试过的修法**都失败了**

`dev/reports/P1_P2_20261010.md` §2 记录了一次完整的实施→验证→回退：

| 尝试 | 结果 |
|---|---|
| 给方位角加标量速率限制 | 限住 33~52% 帧，**限时方位偏差中位 144~176°**，横向推力损失 **0.5~6.0 m/s²**（与总需求同量级）|
| 改用正确的 `sin(tilt)` 加权 | 仍有害：限帧 4~23%，**夹角中位仍达 8~175°**，损失达 **6.6 m/s²** |

结论（源码注释 `gfold_land.py:1854-1884` 至今保留）：

> 方位角不该被限速，任何形式都会指错推力方向。
> 正确做法是限【三维姿态参考的角速率】，而该机制**已经存在** = `_limit_ref_slew`。

并且实测证明它从未超限：旧程序 3D 参考速率 p90 = 16.9~34.6 < 45，超限帧 0~3%。

### 4.3 旧程序真正的「解法」是**换工况绕过去**

`dev/reports/FIVE_TRIALS_ANALYSIS.md:185`：

```
上一轮的核心问题（公转 1.6 圈、az_err p50=39°）在五趟里都没有复现
  az_err p50:  39.3 -> 0.7 / 2.5 / 13.8 / 3.8 / 1.7
  公转圈数:    1.57 -> -0.00 / -0.08 / -0.02 / -0.02 / -0.47
```

原因：用户把交接初偏从 29 m 改成 166~327 m。

> 首飞是特例：初始 dist 只有 29 m，误差小、倾角需求小，于是**方位角成了瓶颈**。
> 五趟偏移大，瓶颈转移到倾角上。

39 趟全量统计验证（旧 30 趟 + 新 9 趟）：

| dist0 区间 | n | azErr50 中位 |
|---|---|---|
| **< 50 m** | 60 | **14.5°** |
| 50~100 m | 11 | 1.8° |
| **> 100 m** | 8 | **1.6°** |

`corr(dist0, azErr50) = -0.294`

**⇒ 旧程序在小初偏下同样发病。这次 `dist0 = 13.8 m`，正落在发病区间。**

### 4.4 但旧载具「病了也不致命」，新载具「病了就崩」

这是**唯一**真正的载具差异：

```
旧: 方位错 39° -> omega 只到 0.14 rad/s -> 3 帧刹住 -> 误差不累积 -> 振幅 0.14
新: 方位错 60° -> omega 冲到 0.79 rad/s -> 13 帧刹不住 -> 误差继续累积 -> 发散
```

**同一个「方位角无限速」的结构缺陷，在旧载具上是「无害小抖动」，在新载具上是「发散」。**

## 5. 本次修正 A + B

### 5.1 A：`CTRL_X_ROT_KP` 5.0 → **2.0**（回到旧值）

**为什么是 kp 太大，不是 kd 太小** —— P 项单独饱和的门槛：

```
err_sat = 1 / kp_eff = 1 / (kp * sched)

旧: kp=2.0, sched<=1.60 -> kp_eff 峰值 3.2 -> 门槛 17.9 deg
    实测 err_x 中位 3.3~7.5 deg，【永远够不到】=> satX = 0%
新: kp=5.0, sched<=1.90 -> kp_eff 峰值 9.5 -> 门槛  6.0 deg
    实测 err_x 中位 19.9 deg，【是门槛的 3.3 倍】=> satX = 73%
```

实测 `pid_sat_x` / `pid_sat_z`：

```
旧 164053   0% / 14%
旧 124409   0% /  1%
旧 183756   0% / 30%
新 144058  67% / 76%
新 154351  73% / 80%
```

**`pid_px` 一项就能到 2.20 中位、5.91 峰值 —— 是 ±1 的 3 倍。** 这时加 `kd` 毫无意义：P 已经饱和，D 只能在「饱和+一点阻尼」和「饱和+反向阻尼」之间移动。

**闭环复核（参考序列 = 日志 `tilt_cmd` playback，只改 kp/kd）：**

| 趟 | 配置 | maxErr | **omegaPeak** | sat% | 尾部max | 尾部mean |
|---|---|---|---|---|---|---|
| 144058 | kp=5 kd=5 | 23.7 | **0.306** | 27% | 17.6 | 6.8 |
| 144058 | **kp=2 kd=5** | 22.3 | **0.116** | **0%** | 15.8 | 8.7 |
| 154351 | kp=5 kd=5 | 12.2 | **0.165** | 0% | 6.8 | 3.6 |
| 154351 | **kp=2 kd=5** | 17.0 | **0.131** | **0%** | 9.7 | 5.5 |

收益：角速率峰值降 **62% / 21%**，饱和帧 27%/0% → **0%/0%**。
代价：尾部残差略升（6.8→8.7、3.6→5.5 deg），即跟踪变「软」。

### 5.2 B：`REF_SLEW_MAX` 30 → **20**、`TILT_LEAD_SEC` 2.5 → **1.5**

**先说 `REF_SLEW_MAX` 为什么原来定 30 是错的：**

它按「物理上限」选（悬停时 `sqrt(2*10.2*45°) = 30.2`），但**控制器根本跑不到物理上限**：

| 趟 | 3D 参考速率 p50 | p90 | max | ref_clip |
|---|---|---|---|---|
| 旧 164053 | 10.2 | 19.7 | 34.6 | **1%** |
| 旧 143917 | 5.8 | 34.6 | 40.1 | 10% |
| 新 144058 | 14.5 | 24.1 | 27.8 | 16% |
| 新 154351 | 12.0 | 18.6 | 23.2 | **2%** |

**⇒ 把护栏设在「够不到的地方」，等于没有护栏。** 降到 20 后，新 154351 有 3/56 帧（5%）、新 144058 有 14/51 帧（27%）开始被削 —— 与旧程序「只咬掉最激进的少数帧」的设计口径一致。

**`TILT_LEAD_SEC` 才是 B 的核心。** 原来取 2.5 s 的推导是：

```
滞后 ∝ 1/sqrt(alpha)，sqrt(0.35/0.0669) = 2.3 倍 => 2.8~5.0 s
```

**这个推导漏了两点：**

1. **本载具 alpha 与旧载具几乎相同**（13.9~18.6 vs 16.1~16.4），因为引擎数与万向节力矩同步涨了。滞后正比于 `sqrt(I/tau)`，而这个比值的新旧比 ≈ 1，**不是 2.3**。
2. **前赡在「旋转中的方位参考」上不是「补偿滞后」，而是「主动追更歪的方向」。**

实测前赡在方位通道上凭空加大的误差：

| 趟 | 方位参考转速 | 前赡 2.5s 提前量 | 占 az_err 中位 |
|---|---|---|---|
| 旧 164053 | 11.2 deg/s | 16.8 deg | 43% |
| 旧 143917 | 1.6 deg/s | 2.4 deg | 80% |
| 新 144058 | 9.2 deg/s | 23.0 deg | 41% |
| **新 154351** | **19.5 deg/s** | **48.9 deg** | **78%** |

**本载具方位参考一转就 19.5 deg/s，2.5 s 前赡等于把姿态目标往误差更大的方向多推 48.9°。** 这是 `az_err` 长期 60~110° 的**直接来源之一**。

改成 1.5 s 后，提前量按比例降到 60%（29.3°）。

**为什么不取 0 或 1.0**：机身滞后确实存在（旧程序实测 1.2~2.2 s），1.5 s 落在该区间内；再小就等于放弃补偿。

### 5.3 A+B 一起做的效果（闭环）

| 配置 | maxErr | omegaPeak | sat% |
|---|---|---|---|
| 改前 kp5 kd5 lead2.5 | 23.7 | 0.306 | 27% |
| A: kp2 kd5 lead2.5 | 22.3 | 0.116 | 0% |
| B: kp5 kd5 lead1.5 | 27.5 | 0.430 | 27% |
| **A+B: kp2 kd5 lead1.5** | **23.9** | **0.157** | **0%** |

**A 的贡献是决定性的（饱和 27%→0%），B 单独用会让 omega 反而升（0.430），必须与 A 一起。**

## 7. 老实说：A+B 不够

**A+B 消除的是「控制器把误差放大」，但没有消除「参考自己在转」。**

根因链还是完整的：

```
小初偏 dist0=13.8 m
  -> 水平需求小 -> tilt_cmd 只有 14 deg
  -> 低倾角下方位角的 3D 代价 = sin(tilt)*d_az 极小 -> _limit_ref_slew 完全放行
  -> 方位参考累计转 568 deg（1.58 圈），载具跟着绕目标 1.21 圈
  -> ???  <-- 这一步仍然没人管
  -> 姿态误差累积（A 已缓解）
```

**这一步旧程序也没管**，它是靠「喂大初偏」绕开的。

**三个仍然开放的候选（都需要你先决定）：**

| # | 动作 | 依据 | 风险 |
|---|---|---|---|
| **C** | 把 `TILT_AZ_MIN_ERR` 从 1.5 提到 8~10 m | 位置误差小时冻结方位，避免噪声驱动；实测 1.5 m 只在大约 2 帧内生效，随后被冲开 | 低 |
| **D** | 水平律改用**径向优先**（`a_h` 只用误差径向分量） | `FLIGHT_20261008_ANALYSIS` F2：31% 的帧在「推离目标」，切向占比 p50=0.25 | 中（改变律） |
| **E** | 接受「小初偏特例」，把交接门放宽到 `dist0 > 50 m` | `FIVE_TRIALS` 的原始做法 | **不是修复，是掩盖** |

**我建议先飞 A+B 验证，再决定 C/D** —— 因为 A+B 已经改变了 `omega` 和 `satX` 的量级，C/D 的效果要在新基线上重新评估。
