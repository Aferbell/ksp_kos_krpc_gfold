## 2.5 ⚠️ 但我必须告诉你：这个改动会让圆化【略微变差】

**我用两种互相独立的方法做了检验，结论一致。**

### 方法一：高斯变分方程（解析）

圆化的目标是**把近地点抬高**，即最大化
```
drp/dt = (da/dt)(1-e) - a(de/dt)
```
把推力方向写成 φ（从当地半径方向量起，φ=90° 就是"当地水平"），
则 `drp/dt = acc·(A_r cosφ + A_t sinφ)`，最优方向 `φ* = atan2(A_t, A_r)`。

实测（acc=30 m/s²，转移轨道 a=409 km、e=0.7115）：
```

    165     30.49 |    6293.6    5358.4    6294.9 |    91.2    90.0    59.5
```

### 结论与物理原因

> **两种方法一致：瞄准"当地水平"比"轨道顺向"把近地点抬得【更快】；
> 最优方向是 85~95°（≈ 当地水平），而不是顺向的 (90°−γ)。**

**物理原因**：抬高近地点需要**角动量**。当地水平的推力**完全垂直于半径**，
所以它的力矩 100% 用于增角动量；而顺向推力有径向分量，
那部分分量只增能量、对"抬近地点"效率更低。
**只有在远地点那一瞬间（γ=0）两者才完全重合。**

**⇒ 你现有代码（`aim_mode=2`）本来就接近最优，改成顺向会让圆化变慢 4~20%
（燃烧越长、γ 越大，差距越大）。**

### 那为什么"想改"可能是合理的？几种可能

| 情形 | 是否该改 |
|---|---|
| 只是"觉得顺向更符合直觉" | ❌ 不该改（本分析） |
| **点火时机偏差大**（错过远地点，γ 很大） | ❌ 更不该改 —— γ 越大，水平的优势越明显 |
| 目标其实是**抬远地点**（不是圆化） | ✅ 该改（但那就不是圆化了） |
| 想与**目标轨道共面**（plane matching） | ⚠️ 那需要的是法向分量，两者都不对 |
| 想**减少姿态机动量**（少转一次） | ✅ 有边际收益：§7 已用模式 1，圆化沿用模式 1 ⇒ 少一次 30° 级转向 |

**⇒ 如果动机是最后一条（省一次转向），那是有道理的，但代价是圆化效率略降。
建议：先按现状飞一次、记录 `t_burn` 与最终 `pe/ecc`，再改成模式 1 飞一次，
用实测数据定夺 —— 这比我再怎么算都可靠。**

## 3.3 拟用制导律（已用真 Mun 参数仿真验证）

### 三段结构

```
段 A  脱离段（滑行）   100 km 圆轨 -> deorbit 40 m/s -> 滑到 15 km
段 B  制动段（主减速） 15 km 高度，594 m/s 水平速度 -> 消掉大部分
段 C  末段（触地）     高度 < ~200 m，横速已消 -> 立直 + 垂速闭环
```

### 制导律（核心公式）

**① 竖直 (沿用本项目已验证的 `a_need` 比例律)**
```
a_need = g + (vz² − vz_tgt²) / (2·h)          h = 剩余高度（下限 0.5 m）
```
**为什么用它**：它的等效增益 = `vz/h`，随 `h→0` 自动变大，
**不需要调增益**。本项目在 Kerbin 一级上已实飞验证过这个结构
（`gfold_land.py` 的 `a_ver_need`、`B1040-9.ks` 的 `a_h_stop` 同型）。
**参考仓库那个固定增益 PID 在低 g 下会在末段欠刹车**（这正是本项目
`GFOLD_FINAL_SEGMENT_FIX.md` 记录过的坑：弱 P 环给 16.5 而需要 20.3 ⇒ 落地 −12.2 m/s）。

**② 水平（非定点的关键）**
```
a_h = −(kv·vh + kp·dp)         非定点：令 kp = 0（或极小）
```
- `kp = 0` ⇒ **只消横速、不追位置** ⇒ "落到哪算哪"，这就是**非定点**
- 若想半定点，可取 `kp = 0.001`（只在远处轻微纠偏）
- **注意**：`kp=0` 时落点散布 ≈ 初始横速误差造成的位移，**这是设计选择不是缺陷**

**③ 姿态（推力沿机身 ⇒ tilt 直接决定水平推力）**
```
tilt = atan2(a_h, a_up)         再夹到 tilt_max
```
这与本项目 `gfold_land.py` 的"倾角第一性律"完全同构
（`_tilt_cmd = atan2(_ah_cmd, a_up)`）。

**④ 油门**
```
thr = |a_cmd| / (F/m)
```

**⑤ 姿态控制**：自写 pitch/yaw/roll PID 写 `control.pitch/yaw/roll`，
**`sas off`、`rcs on`**（与参考仓库第 7 条一致）。

## 3.6 ⚠️ 必须诚实说明的风险与不确定项

1. **我的仿真是"点质量 + 无姿态动力学"**：忽略了
   (a) 姿态环滞后（本项目实测在 Kerbin 上是 0.6~0.8 s、已在 224111 里
       造成 20° 级偏差）、(b) 发动机摆动延迟、(c) 燃料晃动。
   **⇒ dv 需求有 5~15% 的不确定性，必须留余量。**
2. **`a_need` 律在"h→0"处有 1/(2h) 奇异**：我用 `h_floor=0.5 m` 兜底，
   但真实末段必须靠**触地判定**收油（`h<10 m` 或 `situation=landed`），
   不能只靠这个式子。
3. **我不确定你的 Mun 着陆级推重比是多少**：
   仿真显示 **TWR < 1.6 就不可能安全着陆**。**这是必须先确认的数**——
   若实际 TWR 只有 1.2，则无论怎么写程序都落不下去（需要改载具）。
4. **非定点的"落点散布"我没有定量给出**：因为 `kp=0` 时散布取决于
   进入误差与横速误差的传播，需要你告诉我可接受的散布范围
   （例如"±500 m 内皆可"），我再据此定 `kp`。
5. **参考仓库只借了"结构"**：它的 PID 参数（Kp=0.01/Kd=0.03、
   pitch_bias=−10°）是针对**有大气、高 TWR 的星舰**，**不能照抄**。
6. **我没有读取你的 Mun 载具文件**：方案里的 `m0`/`F`/`Isp` 都是我
   假定的值（15000 kg / TWR 2.5 / Isp 320 s）。**看到载具后才能定参数。**

# 四、本次分析的自我修正记录

我在推导 stage2 结论时**连续犯了 5 个错**，前 4 个导致结论反复翻转，
必须记录以免误导：

| # | 错误 | 后果 | 修正 |
|---|---|---|---|
| 1 | 用 `rp >= 700 km` 收油，但**该判据一旦满足就永远满足**（rp 钉在 700） | 仿真烧到超时，dv 虚高 3.4 倍 | 改用**单次冲量扫描**（无积分误差） |
| 2 | **kRPC 日志 `mass` 单位是 kg**（不是吨，与 kOS 日志不同） | 曾乘 1000 ⇒ 全部 infeasible（假结论） | 修正单位 |
| 3 | `solve_p3p4_state(x0, mass)` 的 **`x0` 是 6 维** | TypeError | 修正签名 |
| 4 | **反向积分符号弄反**（应当取远地点【之前】的状态） | γ 的符号错，而符号正是本问题的核心 | 用 `-h` 步长反向积分 |
| 5 | 固定燃烧时长但没让燃烧**以远地点为中心** | 两条律的对比区间不一致，结论随 t_burn 翻转 | 燃烧以远地点为中心 + 加自校验 |

**最终采用的两条证据链都做了自校验**：
- 解析：最优圆化 dv = **1040.0 m/s** vs 理论 **1039.67 m/s**（差 0.33）
- 数值：`acc=2000, t_burn=2s → best_e=0.00166, dv=1040.00`

**且两条链（高斯变分方程、单次冲量扫描）互相独立、结论一致。**
