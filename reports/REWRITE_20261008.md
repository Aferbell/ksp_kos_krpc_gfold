## 3. 结构变化

**旧版**：两条并行律（旧律 + 倾角第一性），由 `TILT_FIRST_ENABLE` 切换，
另有 try/except 回退分支。`tilt_cmd == tf_cmd` 在 4 趟共 **391/391 帧**成立
⇒ 旧律路径**已死**，但 `target_a` 仍间接活着（它的模喂给 `_amag`）。

**新版**：单一 tilt-first 律，无开关、无回退。竖直与水平**彻底分离**：

```
外环  水平: a_h_vec = u_h + kv·dve + kp·dp     T = clamp(2|dp|/|dve|, 6, 8)
             kv = 4/T, kp = 6/T²  =>  zeta = 0.816 与 T 无关
      竖直: a_up = u_i[0] + K_VEL·Δvz + K_POS·Δalt   ← 真正的竖直 PD
内环  状态是 a_h（不是倾角），限 |da_h/dt| <= j_max
      j_max = a_up·sec²(θ)·sqrt(2·α·headroom)   ← 由权限在线导出
      最后 tilt = atan2(a_h, a_up)              ← 由 a_h 反解
```

## 4. 措施 2 与措施 3（按用户要求一并修）

### 措施2：内环改限**加加速度**

旧版限的是**倾角速率**，经 `a_h = a_up·tan(θ)` 映射后等效 jerk 为
`j = a_up·sec²(θ)·slew`，而 `sec²` 在 1.04~1.49 漂、`a_up` 在 5.7~22.6 漂
⇒ 等效 j 失控。实测现行限速只给 **1.40 m/s³**，需求 **2.20**（**59.3% 帧超限**），
物理上限 **7.10**（还有 3.2 倍余量）。

新版把状态量改为 `a_h` 本身，直接限 `|da_h/dt|`，且 `j_max` 由 α 在线导出。
验证结果（`verify_rewrite.py`）：

```
j_max 随 alpha 变化    p50=2.70   max=4.97   （不是固定的 2.0 兜底值 ⇒ α 确实采到了）
|j_used| <= j_max      41/41 帧成立
```

### 措施3：口径闭环

旧版前向用 `a_up_est = max(1,|u[0]|)`、后向用 `av_up`，两者不等
（实测失配 p10=0.518 / p90=1.721）。新版 `tilt` 由**同一个 `a_up`** 反解：
`tilt = atan2(a_h, a_up)` ⇒ 恒等式精确成立（实测偏差 **0.0000 m/s²**）。

> 注：单独做措施3 会让 p90 恶化 46%（失配因子与限速因子负相关 −0.461），
> **必须与措施2 同时做**。两者在同一处改动里自然合一。

## 8. 重写过程中发现并修掉的**真 bug**（4 个）

这些都是"能跑但算错"的类型，静态检查查不出，靠 §6 的闭环验证暴露：

1. **`a_up` 被错误地整体限到 `0.99·g0`**
   `0.99·g0` 只应给**保底值**封顶。整体封顶后净竖直恒为负、**永远无法减速**
   ⇒ 落地垂速 **−116.6 m/s**。修正后 −3.76 m/s。

2. **竖直 PD 误用前赡点**
   前赡点是补偿**姿态**滞后的（机身转动惯性 1.2~2.2 s），而**油门没有这种滞后**。
   用前赡点作参考 = 让推力去追一个"还没到"的未来状态 ⇒ 落地垂速 **−24.0 m/s**。
   改用当前节点后 −3.76 m/s。

3. **能力夹限放在限速器之后，且状态存的是夹限前的值**
   ⇒ 输出被拉低的幅度不受 `j_max` 约束，实测 `j_used` 冲到 **38.997**
   （`j_max` 只有 4.969，**超 7.8 倍**）⇒ "限加加速度"形同虚设。
   修正：先算能力可行的目标，再限速，且**把实际输出作为状态**。
   现在 `j_used` 与 `j_max` 完全一致。

4. **终端收倾角写成 `_tilt_allow = min(_tcap, _tilt_want)`（循环定义）**
   `_tilt_want` 就是**需求**，于是上限恒等于需求 ⇒ `ah_sat` 每帧都是 1、
   能力夹限形同虚设，且 `tilt_cmd` 被钉在需求上、**内环限速完全失效**。
   修正：终端收缩的是**能力上限**，不是需求。
