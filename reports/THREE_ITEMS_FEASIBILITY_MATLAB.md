## 1. 措施一：消除幅值串扰

### 1.1 串扰本身已确证（**这一条是硬的**）

```
|av_up - |target_a|·cos(tilt_cmd)|  max = 0.0011
```

竖直推力幅值确实取自**旧律 PD 向量**的模，而它含水平修正。
子代理独立复核并给出更锐利的表述：**去掉 conic_clamp 的托底后，
竖直 PD 原始值在 72/123 = 58.5% 的帧为负（中位 -8.10 m/s²）**，
只有 conic_clamp 的下限把它托成正的。
**⇒ 所谓"竖直通道"其实是一个下限在承重的空壳，不是一条律。**

### 1.2 开环筛查：PD 形式翻负，加限幅后消失

| 形式 | `a_up<0` 占比 | p10 |

| 加 `[0.5,1.5]·av_plan` 限幅 | **0.0%** | +2.81 |

早期过推比 `av_up/av_plan`：**1.94 → 0.52**。

## 2. 措施二：内环改限加加速度

### 2.1 单位更正（我先算错过）

`tf_slew_allow` 是 **deg/s**，直接代入会把 `j_eff` 放大 180/π 倍
（初版得 80 m/s³，正确值 1.40）。**已修正。**

### 2.2 预算对比

```
sec²(tilt_cmd)          p50 = 1.154        （倾角→a_h 的非线性）
现行限速等效 jerk        p50 = 1.40 m/s³
制导需求 jerk            p50 = 2.20 m/s³
需求/上限               p50 = 1.60  →  59.3% 的帧需求超限
物理 jerk 上限（由 α）    p50 = 7.10 m/s³
```

**⇒ 现行 limiter 结构性不足**（59.3% 帧超限），
而**物理上限还有 3.2 倍余量**。改用 `j_max` 是有依据的。

**建议 `j_max`**：
```
j_max = av_up · sec²(θ) · sqrt(2·α·REF_SLEW_HEADROOM_DEG)    （随 α 在线导出）
固定值备选 ≈ 3.0 m/s³（落在现行上限 1.40 与物理上限 7.10 之间）
```
