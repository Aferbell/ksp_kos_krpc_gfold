## 1. 落地：程序在 alt=24.20 就认为已落地

### 1.1 日志原文

```
# FIN enter alt=24.20 vz=-12.40 vh=0.98
# LANDED   alt=24.20 vz=-12.40 vh=0.98 dist=17.15 tilt=3.20 fin=0.00
```

`fin=0.00` 说明 **FIN 段一帧都没执行**，进入即退出。

对照代码 `starship_land.py:2769`：

```python
if self.nav_mode == "fin":
    _situ = self.v.situation.name
    if _situ == "landed":
        break          # <- 这里，判断优先于任何控制
```

### 1.2 这个 landed 是可疑的

同一帧 `vz = -12.40 m/s`。**一个静止在地面的载具不可能有 -12.4 m/s 的垂速。**

倒数第二帧 `alt=28.09 / vz=-16.76`，0.3 s 后才 `alt=24.20`。
0.3 s 内掉 3.9 m，平均 13 m/s，与 `vz` 一致 —— **它还在飞，不是砸在地上**。

### 1.3 历史数据：直立着陆的真实高度

| log | LANDED alt | LANDED vz | tilt | 姿态 |
|---|---|---|---|---|
| 20261020_190025 | 4.56 | −0.34 | 83.33 | 翻倒 |
| 20261020_202734 | **4.34** | −2.69 | 0.00 | **直立** |
| 20261021_135036 | 4.52 | −0.46 | 106.37 | 翻倒 |
| 20261021_144058 | 5.54 | −10.49 | 83.62 | 翻倒 |
| 20261021_154351 | **1.25** | −11.99 | 6.48 | **直立** |
| 20261021_184650 | **24.20** | **−12.40** | 3.20 | 直立但还在掉 |

**两趟直立着陆的 alt 是 1.25 和 4.34 m，最远不超过 5.5 m。**
184650 报 24.20，比它们高 20 m 以上。

### 1.4 surface_altitude 的语义（kRPC 文档原文）

```
Flight.surface_altitude:
  "The altitude above the surface of the body or sea level, whichever is
   closer, in meters. Measured from the center of mass of the vessel."
```

两个关键点：

1. **"or sea level, whichever is closer"** —— 不是纯粹的"到地形"，
   而是「地形」和「海平面」取**较近者**。
2. **"Measured from the center of mass"** —— 是到**质心**，不是到**着陆腿**。
   Starship 一级长约 70 m，质心在几何中心附近，意味着
   **腿触地时质心还离地几十米**。

**⇒ `surface_altitude=24.20` 完全可能是「质心离地 24.2 m，腿已经触地」。**

**⇒ 我们一直用「质心高度」当「腿触点高度」，这个口径从一开始就是错的。**

## 2. 姿态：这次是低油门段 alpha 塌陷

### 2.1 指标对比（三趟，注意 tilt 需求完全不同）

| log | tilt_cmd p50 | tilt_cmd max | att_err p50 | att_err max | satX | satZ |
|---|---|---|---|---|---|---|
| 172305 | 2.3 | 6.5 | 2.2 | 5.8 | 3% | 1% |
| **184650** | **9.3** | **31.9** | **10.1** | **31.9** | **21%** | **32%** |
| 154351 | 14.4 | 30.9 | 41.7 | 68.3 | 70% | 83% |

**这三趟不能直接比**：tilt_cmd 需求差 6 倍（2.3 vs 14.4），姿态难度本身就不同。

### 2.2 真正的机制：油门掉到悬停的 46%，alpha 塌了 2.9 倍

| t | alt | thr_cmd | av_plan | alpha | slew_max | tilt_cmd | att_err |
|---|---|---|---|---|---|---|---|
| 6.54 | 578.2 | 0.237 | 3.14 | 11.4 | 32.0 | 12.0 | 11.9 |
| 6.93 | 556.7 | 0.200 | 3.14 | 10.1 | 30.1 | 17.5 | 15.2 |
| 7.37 | 534.7 | 0.173 | 3.15 | 8.7 | 28.0 | 23.0 | 16.5 |
| 7.90 | 507.1 | 0.153 | 3.15 | 8.0 | 26.7 | 28.7 | 19.6 |
| 8.21 | 490.9 | **0.147** | 3.20 | **7.7** | **26.3** | **31.4** | **20.2** |
| 8.78 | 458.9 | 0.143 | 3.51 | 7.5 | 26.0 | 31.5 | 16.0 |

**因果链：**

```
av_plan = 3.15 m/s2      规划要求净向下 6.7 m/s2，即"主动加速下坠"
  -> _gfold_floor_effective 判据 plan_a_up - g0 < 0  =>  放开油门下限
  -> min_mag_eff 掉到 3.21~3.58（= a_cap 的 10.5%）
  -> thr_cmd 掉到 0.143（= 悬停 0.308 的 46%）
  -> alpha 正比于油门  =>  从 22.1 掉到 7.5 deg/s2（2.9 倍）
  -> slew_max = sqrt(2*alpha*45deg) 从 44.5 掉到 26.0 deg/s
  -> 同期 tilt_cmd 要求从 12.0 涨到 31.9（速率 34.5 deg/s）
  -> 需求 34.5 > 能力 26.0  =>  追不上  =>  att_err 到 20 deg
```

### 2.3 和 172305 的区别

| | 172305 | 184650 |
|---|---|---|
| tilt_cmd max | 6.5° | **31.9°** |
| thr_cmd 最低 | 0.42 | **0.143** |
| alpha 最低 | 15.9 | **7.5** |
| 饱和 | 3% | **21%** |
| att_err p50 | 2.2° | **10.1°** |

**172305 油门一直在 0.42 以上（> 悬停 0.308），alpha 有 16+，姿态稳。**
**184650 的规划要求"加速下坠"，油门掉到 0.143，姿态权限跟着塌。**

## 3. 问题链（三条串起来）

```
① 规划为了"准点到达"，在 400~600 m 段要求 av_plan=3.15
   => 主动加速下坠 => 油门 0.143 => alpha 7.5 => 姿态追不上

② 姿态追不上 => tilt_act 落后 tilt_cmd 20 deg
   => 水平推力方向偏 => vh 从 1.0 涨到 17.8 m/s
   => dist 从 0.62 涨到 30.2 m => 飞过目标再飘回来

③ 到 alt=28 m 时 vz=-16.76（规划只要 -2.34，差 14.4 m/s）
   => FIN 门（28.0）刚好在这里 => FIN 接管
   => 但同一帧 situation=landed => fin=0.00s => 直接退出
```

**② 里 vh 涨到 17.8 是个新问题**：172305 的 vh 最大只有 2.8。
这趟 dist 从 0.62 涨到 30.2 m 再回 17.1，**是典型的水平极限环**。
累计绕目标只有 17°，不算公转，但**径向冲出去了**。

## 4. 我上一轮的错误（必须承认）

我说「FIN_ALT=10 能兜住 20.3 m/s 的入口速度」。

**这是纯静态计算，前提是「地面高度已知且正确」。这个前提不成立：**

```
我假设：TARGET_ALT = 18（用户实测雷达高度）
实际：surface_altitude=24.2 时 situation 已经报 landed
     => 18 这个数【不是 surface_altitude 的读数口径】
```

两个可能：

| 可能 | 说明 |
|---|---|
| (a) 18 是 kOS 的 alt:radar（到地形，从船体参考点量），而 kRPC 的 surface_altitude 是到质心 |
| (b) 18 是别的高度（比如腿展开前的读数、或另一个地形点） |

**无论哪种，都必须先确定一个唯一口径，否则门槛链的全部推算都建立在错的基础上。**

## 5. 需要你确认的三件事

### 5.1 你测的「18 m」是什么口径？

| 选项 | 含义 |
|---|---|
| (a) | kOS 的 `alt:radar`（到地形，从**船体参考点**量） |
| (b) | kRPC 的 `flight().surface_altitude`（到地形/海平面，从**质心**量） |
| (c) | KSP 界面 HUD 显示的雷达高度 |
| (d) | 别的（请说明） |

184650 那趟 `surface_altitude=24.20` 时 `situation=landed`，
说明**质心离地 24.2 m 时腿已经触地**了。

### 5.2 是不是应该加一个「质心到腿」的偏移量？

kRPC 提供的三个高度**全部是「从质心量」**：

| 属性 | 语义 |
|---|---|
| `surface_altitude` | 地形/海平面取近者，从质心量 |
| `bedrock_altitude` | 到地形（含水底），从质心量 |
| `mean_altitude` | 到海平面，从质心量 |

**没有「到着陆腿」的选项。** 要精确只能自己加一个 `GEAR_OFFSET` 常量。

### 5.3 `situation==landed` 的判据要不要加保护？

现在只要有 `landed` 就 break，哪怕 `vz=-12.4`。
**建议加「vz 也足够小」才认定触地**，否则就是这个结果：

```
alt=24.20  vz=-12.40  situation=landed  ->  break  ->  fin=0.00s
```
