## 0. 先说：我上一轮提的 C 方案是错的

上一份报告第 6 节我写的是「TILT_AZ_MIN_ERR 1.5 -> 8~10 m」。
**这个方案会彻底破坏方位角更新。**

    TILT_AZ_MIN_ERR 比较的是 _perr（前赡点的水平误差）
    实测 _perr 分布:  min=0.09  p50=2.00  p90=4.98  max=5.73 m

**错在哪**：我把 _perr 当成了「当前位置误差」，实际它是**前赡 1.5 s 后那个点**的误差，
天然比当前位置更接近目标（实测首帧 dist_hz=9.42 而 tf_perr=5.73）。

**正确的修法**：不是「提高阈值冻结」，而是「**拒绝大幅跳变**」。

## 1. C：方位角跳变拒绝（AZ_JUMP_MAX_DEG = 60.0）

### 1.1 病根

starship_log_20261021_195348 实测：

    att_err 的 39/47 个超标帧（83%）主因是【方位角翻转 180 度】，不是倾角跟不上
    abs(az_err) > 150 deg 占 31%，符号翻转 3 次

机理：载具穿过目标时 dp 反向 => _ah_vec 方向翻转 => _az 突跳 180 度。
而 tilt 只有 1~8 度，sin(tilt)*daz 的三维代价极小，_limit_ref_slew **完全放行**
（实测 ref_slew p50 只 4.2 deg/s）。

后果：机头被命令绕竖直轴转 180 度，绕圈期间水平推力指向错误方向，
反过来维持水平极限环（实测 dist 0.09~11.54 m，周期 6.35 s）。

### 1.2 阈值扫描（回放本趟日志）

| 方案 | 方位累计转角 | 翻转次数 | 更新帧 | 拒绝帧 |
|---|---|---|---|---|
| 现状（180 = 不过滤） | **-537 度** | **4** | 47 | 0 |
| 拒绝 > 90 度 | +183 度 | 0 | 35 | 12 |
| **拒绝 > 60 度** | **+13 度** | **0** | 30 | 17 |
| 拒绝 > 30 度 | -20 度 | 0 | 27 | 20 |

**取 60 度**：方位角累计只转 13 度（几乎不转），0 次翻转。

**为什么不是 90**：90 度仍留下 +183 度累计旋转（几乎半圈）。
**为什么不是 30**：多拒绝 3 帧收益不大，且过窄的门会让「落点真在侧后方」
的正常方位跟踪失效。

### 1.3 实现

    # starship_land.py track() 的 5 号方位角段
    _az = self.tf_az_dir
    if _ah_dem > 1e-9 and _perr > TILT_AZ_MIN_ERR:
        _az_new = (_ah_vec / _ah_dem).copy()
        _accept = True
        if _az is not None and AZ_JUMP_MAX_DEG < 180.0:
            ... 算 _az 与 _az_new 的夹角 _jump ...
            if _jump > AZ_JUMP_MAX_DEG:
                _accept = False      # 保持上一有效方位
        if _accept:
            _az = _az_new
            self.tf_az_dir = _az

**跳变被拒时**：保持上一有效方位角（等于「暂时不改方向」），
这比「指到反方向」安全得多。等载具重新拉开水平距离、_ah_vec 方向稳定后，
会自动恢复更新。

**AZ_JUMP_MAX_DEG = 180.0 等于关闭该功能**（恢复旧行为），便于 A/B 对比。

## 2. D：加 situation / ut / wall_dt / az_reject / az_jump 五列

### 2.1 为什么需要

| 列 | 解决什么未定项 |
|---|---|
| situation | 判定「假触地」。184650 在 alt=24.20 / vz=-12.40 就报 landed，fin=0.00s |
| ut | sum(loop_dt) 比墙钟少 15%，导致 dvz/dt 被高估到 +38.9（满推上限 23.5）|
| wall_dt | 与 loop_dt 直接对比，一眼看出时标是否一致 |
| az_reject | C 修正是否在起作用（1 = 本帧拒绝了一个大跳变）|
| az_jump | 被拒时的跳变角，用于调 AZ_JUMP_MAX_DEG |

### 2.2 实现

**Logger 列**（starship_ctrl.py）：COLS 155 -> **160 列**，
新增 situation / ut / wall_dt / az_reject / az_jump。

**采样**（starship_land.py 主循环）：

    self.dbg_ut = float(ut)
    self.dbg_wall_dt = float(time.time() - _t_seg0)
    try:
        self.dbg_situation = str(self.v.situation.name)
    except Exception:
        self.dbg_situation = "?"      # kRPC 掉线时不崩整个循环

**退出信息也带上了 situation**（这是 D 最有价值的部分）：

    # 主循环触地
    [done] 触地 alt=25.09 vz=-1.08 vh=3.60 dist=11.54 tilt=3.62 (FIN 3.9s) situ=landed

    # 主循环爬升中止
    [abort] 检测到爬升，退出 vz=5.38 alt=23.44 situ=flying

    # FIN 段爬升中止
    [FIN] 检测到爬升 vz=42.27 alt=17.10 situ=flying，退出

**下一趟只要看 situ= 三个字母，就能立刻区分：**

- situ=landed 且 vz=-12 => **假触地**（读数可疑，需要 abs(vz) 保护）
- situ=flying 且 vz=+5 => **真的在爬升**（控制问题）

### 2.3 本帧**没有**改触地判据

situation == landed 就 break 的逻辑**保持原样**。
理由：TARGET_ALT 刚从 18 改到 26.5，还没实飞验证过；
在高度基准未经验证的情况下再加 abs(vz) 保护，两个变量同时动，出问题无法归因。

**先只观测，等这趟实飞数据出来再决定。**
