## 2. 核心瓶颈：倾角上限 35° 饱和

### 2.1 饱和程度随初始偏移急剧上升

```
  trial     dist0   corr p50  corr p90  corr max   %sat@35
  164053     29.2      12.7      31.3      36.7       5.4%
  172942    166.0       7.6      46.8      63.3      17.4%
  172435    215.8      19.5      73.6      77.3      42.2%
  173133    219.2      33.4      77.1      78.9      47.8%
  172711    192.2      45.4      72.5      77.8      54.3%
  173443    326.6      38.3      72.2      79.6      55.7%
```

`corr` = `tf_corr` = `atan2(|a_h_vec|, a_up_est)` = **控制律实际需要的倾角**。

**饱和集中在高空大偏移段**：

```
  alt > 200 m 时的饱和率：  172435=69.4%  172711=73.9%  173443=74.2%  173133=65.2%
```

### 2.2 为什么 `a_up` 这么小

**竖直下降率大 ⇒ 竖直推力只需抵消重力**：

```
av_plan ~ 5~10（远低于悬停时的 g0=9.81，因为在下落）
av_need ~ 12~20（上界）
av_up   ~ 11（实际）      =>  油门 0.13~0.18
a_h_max = a_up * tan(35°) = 11.47*0.700 = 8.03
```

**但需求 `ah_dem` 达 6.8~12.7** ⇒ 超限。

### 2.3 控制律需求是规划的 2~4 倍

```
  trial     plan_tilt p50  plan_tilt p90   corr p50   corr p90
  164053          1.5        9.0          12.7       31.3
  172942          5.2       10.2           7.6       46.8
  172435          7.3       16.3          19.5       73.6
  173133          9.0       20.3          33.4       77.1
  172711          4.1       12.3          45.4       72.5
  173443         14.0       32.4          38.3       72.2
```

规划自己的倾角 p50 只有 1.5~14°，**但控制律要 12~45°**。
⇒ **不是规划要求大倾角，而是误差反馈项把它顶上去了。**

## 4. jerk 违约的真实原因（已定位）

首飞 0 违约，五趟出现 11+1+2 帧。**原因是我设计里的"能力上限优先"路径**：

```
  t   j_used  j_max  ratio  ah_cmd  ah_dem  ah_sat  cap_bind
1.26   17.10   7.50   2.28    4.44   16.00     1        1
1.43   10.30   3.90   2.64    2.79   16.64     1        1
8.18   14.50   6.40   2.27    4.57   13.66     1        1
```

**机制**：`a_h_max = a_up·tan(tilt_allow)`，而 `av_up` 会**逐帧大幅下降**
（实测 `av_up: 10.74 → 6.34`，一帧掉 4.4）：

```
  av_up 掉 4.4  =>  a_h_max 掉 3.1 (7.52 -> 4.44)
  => 输出被硬压下来，|Δa_h|/dt 超出 j_max
```

**这是我明确写下的设计取舍**（`track()` ⑧ 的注释）：
> 能力上限是硬安全限，可以覆盖加加速度限制……不能为了满足 jerk 曲线而超发。

**验证脚本当初只用了一个良性场景**（`av_up` 平稳），所以没测出这条路径。

**✅ 已逐帧核实：14 帧违约【全部】落在 `cap_bind=1` 的帧上**

```
  164053   no violations
  172435   no violations
  172711   11 violations, all on cap_bind=1 ? True
  173133    1 violations, all on cap_bind=1 ? True
  173443    2 violations, all on cap_bind=1 ? True
```

⇒ **行为与设计完全一致，不是缺陷。**
但 `verify_rewrite.py` 的 H3 判据应当补上"`cap_bind=1` 的帧豁免"，
否则将来更严苛的场景会误报失败（本轮的测试场景太温和）。

**⇒ 可优化点**：`av_up` 一帧掉 4.4 m/s² 本身偏猛，
应查为什么 `a_ver_need`/PD 会让竖直指令这么跳（见 §6）。

## 6. 其它观察

### 6.1 落地垂速偏硬，且与偏移正相关

```
  land vz:  172435=-1.64  172942=-6.75  164053=-6.64  173133=-9.55  172711=-10.78  173443=-10.63
```
首飞 -6.64，五趟最差 -10.78。**`av_need = g+(vz²−2²)/(2h)` 在 `h→0` 时爆炸失效**
（上一轮已指出），偏移大时更来不及刹。

### 6.2 帧率稳定但偏低

```
  loop Hz: 5.32~5.41（六趟一致）
```
**姿态 PID 每秒只更新 5.4 次**。倾角指令 `d(tilt_cmd)/dt` 峰值 27 deg/s，
5.4 Hz 采样下相位滞后可观。**这是硬件/通信限制，不是代码问题**，
但意味着"提高外环增益"这条路天然受限。

### 6.3 内环 `j_max` 有裕度

```
  j_max p50: 7.40(首飞) ~ 12.85(173443)，随 alpha 在线导出正常
```
`j_max` 随油门/权限变化，机制工作正常。

### 6.4 `%push away`（推离目标）普遍 20~56%

`172942` 达 55.8%。这与"先发散"瞬态一致：初始速度误差指向外侧时，
短时推力确实朝外。**属正常瞬态**，但数值偏高值得关注。

### 抬高倾角上限的量化收益（纯静态计算）

```
  上限     水平能力倍数      饱和帧占比变化（以 173443 为例）
   35°      1.00x            55.7%
   40°      1.20x            48.9%
   45°      1.43x            45.5%
   50°      1.70x            39.8%
   60°      2.47x            27.3%
```

**代价**（`a_total = a_up/cos(cap)`）：

```
  %-8s     a_up   thr@35   thr@45   thr@50   thr@60
  173443   12.22   0.166    0.193    0.212    0.273
```

**⇒ 即使 60°，油门也只到 27%，推力远未用满。**

**竖直余量**（`a_up = a·cos(tilt)` 的余弦损失）。

**⇒ 建议分两步**：先抬到 **45°**（能力 +43%，油门仅从 0.166 升到 0.193），
飞一趟看姿态与落地表现，再决定是否继续抬。
