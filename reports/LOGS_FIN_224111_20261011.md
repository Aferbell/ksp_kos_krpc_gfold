## 2. FIN 段改动：落地后不关 RCS/SAS，姿态交给 SAS 径向

### 2.1 你的观察与我的核对

你说："**rcs 是一直开着的，只要落地后开启 sas 瞄准轨道径向向外就可以了**"。

我核对了源码，**确认 kRPC 从来没有关过 RCS/SAS**：
```
gfold_land.py 里 control.* 的写入只有：
  throttle / pitch / yaw / roll / gear        <- 没有 rcs/sas
```
而 kOS 那行 `rcs off.`（L1666）**在交班路径里根本不会执行**
（交班后 `gfold_armed=True` 走的是 L1659-1661 的"什么都不做"分支）。
**⇒ 与你的观察完全一致：RCS 全程开着，不需要改。**

### 2.2 实际改动（一处，主循环之外）

**位置**：`gfold_land.py` 收尾段（现 L4466-4488）
```python
if not self.args.dry_run:
    self.v.control.throttle = 0.0
    #  只对【真正落地】生效；超时/爬升等异常出口不改行为
    if landed:
        self.v.control.rcs = True
        self.v.control.sas = True
        self.v.control.sas_mode = SASMode.radial    # 径向向外
        self.dbg_post_sas = 1.0
```

**三个必须说清的设计点**：

1. **为什么必须显式打开 SAS**：本进程结束后就不再写
   `control.pitch/yaw/roll`。此时若 SAS 关闭，姿态**没有任何东西维持**，
   一级会在触地后慢慢歪倒。径向模式让机头保持指向天顶，
   **与 FIN 律的目标一致**，正好实现"保持原来的指向"。

2. **为什么必须放在循环【之外】**（**关键，否则会把飞行搞坏**）：
   SAS 一旦打开，KSP 会**忽略** `control.pitch/yaw/roll` 的写入。
   若在循环内打开，FIN 律（以及 gfold 段）的姿态控制**立刻失效**。
   放在这里 = 主循环已退出、不再输出控制量的时刻。

3. **为什么只对 `situation=='landed'` 生效**：超时/爬升等异常出口不应强行
   给 SAS 模式（可能正在爬升，径向保持没有意义），
   **保持异常场景的既有行为不变**。

**异常安全**：`situation` 读取与 SAS 设置各自 `try/except` 包住，
任何异常都不会让收尾路径崩掉（崩了就不写日志、也不给 SAS，反而更糟）。

**⚠️ 一处需要你实机确认**：`SASMode.radial` 我已用本机 kRPC 0.6.0 核对
存在（`value=6`），但**"径向"在 KSP 里是相对主天体还是相对轨道面**，
取决于游戏设置；若你希望的"径向向外"与此不同，告诉我改成
`SASMode.anti_radial` 或别的模式即可。

## 4. 224111（=日志 223914）起振分析：为什么"对准很好、规划简单"仍会振

**对应关系**：`屏幕录制 2026-10-10 224111.mp4` ↔ `gfold_log_20261010_223914.csv`
**时间对齐**：`video_time = 25.34 + log_t`
（视频 51.03 s、1920×1080、30 fps；log 首帧 wall=22:40:45，视频起点 22:40:19）
⇒ **gfold 段在视频 25.3~38.9 s**。

### 4.1 起手条件（这是理解起振的钥匙）

```
接手时（gfold 首帧，t=0.20）：
  alt   = 648.3 m       vz  = -68.03 m/s
  dist  =  10.69 m      vh  =   6.54 m/s
  tiltA =   5.61 deg    tiltC =  2.05 deg
  a_up  =   4.47 m/s^2  a_h   =  0.16 m/s^2
  规划 tf = 12.5 s
```

**关键算术**：`dist / vh = 10.69 / 6.54 = **1.63 s**`
—— **横速只要 1.6 s 就会把载具带过目标，而规划还有 12.5 s。**

**⇒ 制导此时要做的不是"大机动"，而是"精确抵消这 6.5 m/s"。**
而抵消它需要的 `a_h` **很小**（`dist` 小 ⇒ 位置项小，实测 `a_h=0.16`），
于是指令倾角也只有 **2~13 deg**。

**这就是"应该不需要太大机动"的定量解释 —— 需求确实很小。**

### 4.2 但"小需求"撞上了"姿态环的固定滞后"

### 4.3 小倾角把"相对误差"放大到极致

因为推力沿机身，**实际水平推力 / 期望水平推力 = tan(tiltA) / tan(tiltC)**：

```
     t |  tiltC  tiltA |  tanA/tanC |  水平力误差
  0.20 |   2.05   5.61 |     2.74   |    174%
  0.65 |  11.53   5.20 |     0.45   |     55%
  2.12 |  21.02  12.95 |     0.60   |     40%
  3.05 |  14.95  20.34 |     1.39   |     39%
  3.31 |  10.49  21.57 |     2.14   |    114%
  3.50 |   6.64  22.21 |     3.51   |    251%
  3.70 |   2.51  22.07 |     9.25   |    825%
  3.92 |   1.52  21.15 |    14.58   |   1358%   <- 极端
  4.42 |  10.76  16.56 |     1.56   |     56%
```

**⇒ 当指令倾角小到 1.5~2.5 deg 时，同样的姿态滞后会让水平推力
错 10~15 倍。** 这是"**小需求反而更容易振**"的核心机制：
**需求越小，姿态滞后的相对影响越大。**

### 4.4 为什么振幅会增长（自激）

**每次穿越目标时的残余横速**（`dist` 局部极小）：
```
    t= 2.12  dist= 0.79  vh= 4.30   -> 穿越时【还带着 4.3 m/s】
    t= 3.70  dist= 4.34  vh= 0.32   -> 这次收得好
    t= 4.94  dist= 0.87  vh= 5.54   -> 【还带着 5.5 m/s】
    t= 8.89  dist= 1.51  vh=12.26   -> 【还带着 12.3 m/s】
```
**⇒ 穿越时的残余横速一次比一次大（4.3 → 5.5 → 12.3 m/s）。**
"消横速"没做完 ⇒ 冲得更远 ⇒ 回来时误差更大 ⇒ **振幅增长（自激）**。

**成因**：姿态滞后 0.6 s 意味着**推力方向的修正总要晚 0.6 s**；
而穿越大致每 1.5~1.9 s 一次（`dist` 半周期）——
**滞后占了穿越间隔的 1/3**，于是每次修正都"打在已经过去的事情上"，
**净效果是持续给水平通道泵入能量**。

### 4.5 与"规划很简单"的关系（澄清一个误解）

规划简单（`tf=12.5 s`、`a_h` 需求 0.16~4.8 m/s²）**恰恰是问题的一部分**：
- 需求小 ⇒ 指令倾角小 ⇒ **姿态滞后的相对影响被放大**（§4.3）
- 但姿态环的**绝对滞后（0.6 s）不随需求变小** ⇒ 小指令下它占比更大

**⇒ "规划越简单越不该振"这个直觉在这里不成立**，
因为振荡的成因不是"机动太大"，而是"**姿态响应相对需求太慢**"。

即**发动机摆动（gimbal）幅度很小**，姿态主要由整机转动实现。
所以"箭头歪"就是"推力方向歪"，**姿态误差 = 推力方向误差**。

**⚠️ 必须诚实说明的测量限制**：
- 1920×1080 下箭体仅约 **100×300 px**，喷流更细。
  **gimbal 角（通常几度）在该分辨率下无法可靠分辨**，
  故我**只做"喷流是否偏离箭体轴线"的定性判断，不给数值**。
- 我**尝试**过从像素直接测箭体倾角（PCA 暗像素），
  但方法**失效**：用 `12th percentile` 当阈值会**恒定选出 12% 的像素**
  （实测 26313~36746 ≈ 0.12×343200），掩膜根本没在"选箭体"。
  **该测量已作废**，表中不引用。
