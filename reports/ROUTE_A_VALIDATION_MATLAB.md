## 0. 结论

**路线 A（先修时标）不成立。** 三条独立证据：

1. **规划本身是自洽的** —— 不是"规划时标算错"。
2. **三种时标口径在真实轨迹上给出的竖直指令全部为负**（`a_up < 0` 物理不可能），
   且实时/拉伸口径比现状**更差**（负值占比 82% vs 63%）。
3. **竖直误差的真正来源不是时标**，而是**幅值串扰**：
   `av_up = |target_a|·cos(θ)` 把**水平 PD 修正的幅值**当成了**竖直推力幅值**。

## 1. 证据一：规划自洽（不是时标算错）

把规划的竖直剖面按**它自己的时间轴**取出来，比较两个独立来源：

```
d(plan_vz)/dt        （对规划速度剖面求导）
av_plan - g0         （规划给出的竖直净加速度）
```

| 区间 | `d(plan_vz)/dt` | `av_plan - g0` |
|---|---|---|
| 平台段 `plan_vz=-80` | **0.000** | **0.273** |
| 加速段 `plan_vz<0` 上升期 | **-4.12** | **-4.13** |

两者一致 ⇒ **规划的竖直分量与它的速度剖面自洽**。

（全段 `rms` 差异 6.24 m/s² 主要来自剖面拐点处的**有限差分误差** ——
端点段 rms=16.08 vs 中段 rms=5.26，集中在折点，不是规划矛盾。）

**⇒ "规划 tf=18.5 就是错的、该修"这个前提不成立。**

---

## 2. 证据二：三种时标口径全部给出负的 `a_up`

在**真实飞出的轨迹**上评估三种候选时标（`pos`=现状按位置、`time`=实时推进、
`map`=拉伸到规划末端）：

| 时标 | `a_up<0` 占比 | p10 | p50 | min |
|---|---|---|---|---|
| `pos`（现状） | **0.626** | -18.48 | -8.19 | -20.09 |
| `time` | **0.821** | -183.59 | -98.02 | -190.59 |
| `map` | **0.821** | -89.48 | -52.78 | -90.93 |

**`a_up < 0` 物理上不可能**（推力只能向上推）。

而且**修时标使情况恶化**：实时推进会让载具试图"追赶"规划，
需要的加速度远超物理能力（p10 = -183 m/s²）。

> 补充：我也做了"自由落体最快追赶"可行性检查 —— 规划高度与实测高度
> 在 10/11 采样点可被自由落体重合，但那是**同义反复**：
> `plan_alt ≈ alt` 是**按最近位置选索引**的必然结果
> （`corr(alt, plan_alt) = 1.0000`）。真正暴露问题的是 `plan_vz`
> （不受索引约束）：`corr(vz, plan_vz) = 0.72`，`vz = 0.518·plan_vz - 14.90`。

## 3. 证据三：真正的根因是**幅值串扰**

### 3.1 数据

```
t ≤ 3.0 s :  mean av_up = 10.82   vs  mean av_plan = 5.58   比值 = 1.94
```

**早期竖直推力接近规划的两倍 ⇒ 过度制动。**

早期逐帧：

| t | `\|target_a\|` | tilt | `av_up` | `av_plan` | 旧律竖直分量 |
|---|---|---|---|---|---|
| 0.24 | 15.50 | 0.77° | **15.50** | 5.54 | **-0.70** |
| 0.68 | 11.75 | 5.74° | **11.69** | 5.54 | +2.89 |
| 1.04 | 9.20 | 9.20° | **9.09** | 5.56 | +0.22 |
| 1.74 | 10.13 | 16.42° | **9.72** | 5.59 | -11.14 |

### 3.2 机制

```
av_up = |target_a| · cos(θ)          恒等式，实测偏差 max 0.0011
```

**早期 `tilt` 很小（9.13° 均值，cos = 0.987）**，所以 `|target_a|` 的
**几乎全部**被转成了**竖直推力**。

而 `|target_a|` 来自哪里？—— 2857 行的**旧律 PD 向量**经 `conic_clamp`：

```
target_a = u_i + K_VEL·(v_i-vel) + K_POS·(x_i-error)
```

它含**水平修正**（日志：`pdv_h` p50=5.28、`pdp_h` p50=5.96）。
**这些水平修正的幅值，经小倾角，被当成竖直推力发出去。**

**关键证据（t=0.24 帧）**：旧律向量的**竖直分量只有 -0.70**（甚至为负），
但 `av_up = +15.50` —— 方向被新律改写、幅值却来自旧律。

### 3.3 后果链

```
t=0.24  av_up=15.50 而 av_plan=5.54   →  过度制动
   →  实测 vz 从 -63 迅速回到 -39（规划要 -57～-60）
   →  t=1.89 时 vz 比规划【快 +21.0 m/s】
   →  载具提前"刹住"，随后无法按规划的 -80 下降
   →  累积滞后，13.3 s 后逐渐追上
```

**反事实检验**（竖直推力改为纯前馈 `av_plan`）：

```
mean |vz - plan_vz|  实测      = 17.15 m/s
mean |vz - plan_vz|  纯前馈    = 12.61 m/s
⇒ 仅前馈就消除 26% 的竖直跟踪误差
```

## 4. 对第一步的影响（回答"竖直改 PD 为什么翻负"）

现在可以解释我上一轮遇到的现象了：

**竖直 PD 翻负不是因为时标，而是因为它和幅值串扰叠加：**

```
竖直 PD  = av_plan + 0.8·(plan_vz - vz) + 0.5·(plan_alt - alt)
         = 5.54  + 0.8·(+21.0)          + ...
         = 5.54  - 16.8 ≈ -11
```

那个 `+21.0 m/s` 的 `vz` 偏差**正是幅值串扰造成的过度制动**。
**修时标不会消掉它**（证据二已证反而更糟）。

⇒ **第一步（竖直改 PD）单独做不可行的原因，是幅值串扰，
不是时标。** 我之前把根因归到"时标"是错的。

## 5. 修正后的方案排序

| 优先级 | 措施 | 依据 |
|---|---|---|
| **1** | **消除幅值串扰**：竖直不再取 `\|target_a\|·cos(θ)`，改为**独立的竖直指令** | §3，本条是根因 |
| 2 | 内环改限加加速度（原第二步） | diag60/61（8/8 起点更优） |
| 3 | 口径闭环（`_tcorr` 与后向同 `a_up`） | 须在 1、2 之后 |
| ~~4~~ | ~~先修时标~~ | **本轮证伪** |

**注意**：第 1 条**不等于**我上一轮试的"竖直 PD"。区别在于：

- 上一轮 V-A：`av_plan + KV·Δvz + KP·Δalt` —— 反馈项会翻负
- 现在应做：**竖直指令以规划为主、反馈限幅**
  （例如 `a_up = clamp(av_plan + Δ, av_plan·0.5, av_plan·1.5)`，
  且整体 `≥ AVER_FLOOR`），保证永不为负

而且**必须与第 2 条同时做**（上一轮已证两者耦合）。
