## 二、根因：轨迹在 t=1.5 s 处有「推力悬崖」

用交接点真实状态解出的轨迹（N=80, tf=24.0 s, 每节点 0.30 s）：

| node | t | \|u\| | tilt | 发动机最小油门允许的 \|u\| |
|---|---|---|---|---|
| 0 | 0.00 | **43.33** | 85.00° | 5.42 |
| 1 | 0.30 | 43.31 | 84.29° | 5.44 |
| 2 | 0.60 | 43.49 | 83.59° | 5.46 |
| 3 | 0.90 | 43.67 | 82.88° | 5.48 |
| 4 | 1.20 | 37.89 | 82.18° | 5.51 |
| **5** | **1.50** | **0.82** | **1.89°** | **5.52** ← 断崖 |
| 6 | 1.80 | 0.98 | 25.66° | 5.52 |
| … | … | ~1–5.5 | | |

**`|u|` 在 0.30 s 内从 37.9 掉到 0.82。** 共 **19/80 个节点**（node 5–22 与 79）要求 `|u|` 低于发动机最小油门。

### 2.1 为什么会这样：G-FOLD 的 `norm(u) <= s` 松弛

约束是（`gfold_p3p4.py:350`）：
```python
con += [cp.norm(u[:, n]) <= s[0, n]]     # |u| 的上界 == s，但没有下界
```
以及 `s` 的上下界（`gfold_p3p4.py:367-369`）：
```python
s[0,n] >= mu_1*(...)     # mu_1 = 0.1*T/m  ← 最小油门
s[0,n] <= mu_2*(...)     # mu_2 = 0.8*T/m  ← 最大油门
```

**问题**：`s` 被正确地限制在「最小油门」之上，但 `u` 只被 `s` 从**上界**约束。
`norm(u) <= s` 允许 `|u|` **任意小**（甚至 0），只要不超过 `s`。

求解器因此可以规划出 `s = 5.52`（合规）而 `|u| = 0.82`（**不合规**）的节点。
**物理上：发动机不能把油门降到 0.1 以下** —— 所以 `|u| = 0.82 m/s²` 的节点**飞不出来**。

| | s[0,n] | \|u[:,n]\| | mu_1 | 判定 |
|---|---|---|---|---|
| node 5 | 5.518 | **1.820** | 5.518 | s 合规，但 \|u\| 只有允许值的 33% |
| node 8 | 5.527 | **1.299** | 5.527 | 24% |
| node 13 | 5.542 | **1.497** | 5.542 | 27% |

### 2.2 为什么它恰好毁掉跟踪

跟踪器的**前瞻采样**：
```python
step = min(1.5*N/tf, |vel|/50*N/tf) = 5.0 节点 (= 1.5 s)
_x_i_, v_i_, u_i_ = sample_index(x, u, gfold_n_i + step, tf, N)
target_a_ = u_i_ + (v_i_ - vel)*K_VEL + (x_i - error)*K_POS
```

`step = 5.0` 节点，而悬崖在 node 4→5。
⇒ `n_i = 1` 时前瞻采到 **node 6.0** —— 正好落在死区，`u_i_ = [0.89, 0, -0.43]`，`|u_i_| = 0.98`。
⇒ `target_a_` 由一个**近乎零的向量**构成 ⇒ **方向无意义** ⇒ `target_direction` 塌成竖直。
⇒ `tilt_dir_cmd = 0.00`，而 `tilt_cmd = 80~87`。**完全对应日志。**

> 参考仓库 `demo3_gfold.py` 也有同样的前瞻结构（line 369/379），
> 它的用例入场高度低、tf 短、`step` 小，所以前瞻不会跨到死区。
> 本项目 `tf=24 s`、`|vel|=102 m/s` ⇒ `step=1.5 s` 太长，才让这个缺口显形。

## 三、我在排查中犯的两个错（已回退）

### 错 1：误判「末端节点无约束」为 bug

我一度认为 `for n in range(0, N-1)` 让末端节点 N-1 不受推力上限约束，
并据此改了循环、加了末端上界。

**核查后回退** —— 用**随质量变化的正确上限** `r2/m(z)` 逐节点核对：
```
nodes violating the true bound: 0
node 77 |u|=48.659  bound=48.83
node 78 |u|=48.891  bound=49.06
node 79 |u|= 0.000  bound=49.18
```
全部合规。

**我之前说"18 个节点超限"是我自己的算术错误**：拿了 `r2/m_wet`（用**初始**质量算的常数
43.3）去比，而真实上限随燃油消耗从 43.3 涨到 49.2。

另外末端有 `s[0,N-1]==0` 与 `u[:,N-1]==s[0,N-1]*[1,0,0]`，末端推力被**强制为 0**，
这是原版设计。实测把循环扩到 N 并给 N-1 加最小油门会让问题**立刻 infeasible**
（tf=18…40 全挂），因为它与「末端推力=0」直接矛盾。

### 错 2：未能区分「s 合规」与「|u| 合规」

第一遍检查我看到 `|u| < 0.1·T/m` 就报「违反最小油门」，
但那时我用的分母还是错的。修正分母后才发现：
**s 完全合规，是 |u| 合规性缺乏约束** —— 这是两个不同的量，才是真问题。

## 四、修复方向（需要你决定）

### 方案 A：给 `u` 加最小推力下界（最贴近物理，推荐）

把 `norm(u) <= s` 改为「`u` 必须落在 [min_throttle, s] 的环带内」。
但 `norm(u) >= c` 是**非凸**约束，不能直接进 SOCP。

**G-FOLD 论文的标准做法**是引入松弛变量 `Γ`（`0 <= Γ <= 1`）并约束
`||u|| <= Γ·s_max`、`u[0] >= cos(θ)·Γ·s_max`，再对 `Γ` 的**变化率**加约束
（避免在一帧内从 1 跳到 0）。本项目已有 `pcs` 时变锥，可复用该结构。

> **代价**：改模型必须**重新生成 codegen `.pyd`**（约束是编译时固化的）。

### 方案 B：不加下界，改跟踪器（改动小，不彻底）

问题是前瞻采样跨进了死区。可让前瞻**只在推力连续区内采样**：
```python
# 若 |u_i_| 远小于 |u_i|（说明跨进了死区），就不用前瞻，退回 u_i
if np.linalg.norm(u_i_) < 0.3 * np.linalg.norm(u_i):
    u_i_ = u_i
```
**优点**：不改模型、不用重生成 `.pyd`、立即生效。
**缺点**：治标 —— 轨迹本身仍然飞不出来（node 5-22 要求 0.8 m/s²，发动机实际给 5.4）。
载具会因为「油门降不下去」而多减速 4.6 m/s²，导致**过减速**（vz 偏高）。

### 方案 C：把最小油门从 0.1 降到 0

若发动机允许 `throttle=0`（关机），则 `|u| < 5.4` 合法。
但**关机后无法再点火**（KSP 里 SSME 可重启，但仍有关机-点火延迟），
且 G-FOLD 的连续推力假设会破。**不建议**。

### 我的建议

**先做 B（立即验证跟踪是否恢复），同时准备 A（根治）。**
B 能在下一次实飞就确认「跟踪问题的直接原因是前瞻跨死区」这个判断；
A 才是物理正确的解，但需要重新生成 codegen。
