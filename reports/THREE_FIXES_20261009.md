## 1. ★P1：下降率包络（S2）

### 1.1 先纠正机理 —— 不是「油门顶在下限」

你的判断方向对（上半段姿态权限不足），但**机理要修正**：

| 你的描述 | 实测 |
|---|---|
| 「油门顶在下限」 | ❌ `thr_cmd` 贴合控制器下限的帧 = **0%** |
| | 求解器那个 0.1 下限作用在推力**幅值** `s` 上，对 `|u|` 是**空约束**（26~57% 节点低于它） |
| 「缺乏姿态控制能力」 | ✅ **确认**：低油门段 alpha 10.5，高油门段 22~27，差 **2.05~2.65 倍** |

**真正的因**：控制器竖直前馈直接取规划自己的 `u_i[0]`（`_p0`），
而**规划自己就要低推力** —— 39~66% 的节点 `av_plan < g0`。

### 1.2 关键物理（决定了修法）

```
av_up = g0 - d(vz)/dt
  · vz 恒定（匀速下降）    => av_up = g0 = 9.81  => 姿态权限满
  · |vz| 在变大（加速下降）=> av_up < g0         => 权限不足
总下降量守恒：∫(g0 - av_up)dt = |vz0|   <- "权限亏欠"总量被入场速度定死
```
⇒ **唯一改善办法 = 不把这笔亏欠堆在早期。**
旧包络 `cap[0]` **恒 = 80**（与入场 `|vz0|` 无关，实测 154838 入场仅 −24 也是 80），
于是从 |vz0| 一路加速到 80 —— 这段就是亏欠的集中处。

### 1.3 实现（`dev/solver/gfold_p3p4.py`）

```python
S2_RATIO = 1.05           # vc = S2_RATIO * |vz0|   <- 要求①"随入场速度决定"
S2_VC_MIN = 50.0          # vc 下限（太低会让 P3 无解）
S2_ACCEL_T_MAX = 6.0      # 升到 vc 的时限 [s]      <- 要求③"加速段不能太长"
S2_ENABLE = True
# vc = clamp(1.05*|vz0|, 50, v_descent_max=80)       <- 要求②"有上限"
# slew = (vc - |vz0|)/S2_ACCEL_T_MAX
```

### 1.4 为什么「加速段限时」是必需的（实测，非理论）

```
154838（入场 vz=-24，浅入场）：
  accel_t_max = 3/6/12 s  ->  optimal
  accel_t_max = 1000（即不限制）->  p3 infeasible   ★
```
浅入场时 vc 与 |vz0| 差距大（24→50），立刻允许 50 会与「节点 0 必须满足 |vz|=24」
自相矛盾。**取 6 s 既留过渡，又把加速段限住** —— 这正是你要求③的价值。

### 1.5 实测效果（4 个真实交班状态）

| 工况 | 前1/3段平均 av_up 旧→新 | 低推力帧占比 旧→新 | tf 旧→新 |
|---|---|---|---|
| 154838 (vz0=−24) | 5.13 → **7.32** | 55% → 39% | 23.25 → 30.75 |
| 160001 (vz0=−67) | 8.06 → **9.25** | 31% → 28% | 19.75 → 22.25 |

**代价**：tf 变长、落地质量 −0.8 ~ −1.7 t。
**154838 代价最大**（tf 23.25→30.75），但它也正是姿态权限最差的一趟

### 3.2 旧行为的代码证据

```python
# main() 的 finally: conn.close()          # kRPC 连接关闭，姿态也停更
```
即**姿态与油门全部撒手**。

### 3.3 视频证实（子代理，真帧）

| 项 | 实测 |
|---|---|
| 引擎 | **熄灭**（V1 火焰像素 844→426→69→3；V2 1948→**0**） |
| 停机→触地 | **约 0.8 s**（最后 ~2 m，~2.5 m/s） |
| 姿态 | **不翻滚**；静止约 1 s 后**缓慢单向倾覆** |
| 冲击 | **软着陆**，无爆炸、无弹跳、无碎片 |

**⚠️ 我复核纠正了子代理的一处自相矛盾**：它的收尾摘要说倾覆是 VesselMover，
但它自己实测绿椭圆出现于 **36.53 s**，而倾覆始于 **33.3 s**。
我直接看 `sheets/LEGS.png` / `PLUME2.png`：**v=33.1~33.3 s 已明显倾斜，
画面中没有任何绿椭圆**。按你给的规则（椭圆之前是自由物理）
⇒ **倾覆是失控自由物理，不是 VesselMover。**

### 3.4 日志证据：根本缺陷是「落地时横速没消掉」

| 日志 | 末帧 vh | plan_vh | 末帧 tilt |
|---|---|---|---|
| 154838 | **3.77** | 0.01 | 5.52 |
| 160001 | 1.10 | 0.00 | 6.00 |

规划要求 `vh=0`，实际还有 3.77 m/s；
而既有末段律 `_term_phase` **明确「水平不动」**
（`track()` 内注释原文：*"水平】不动 —— 规划要求 vh=0，继续由水平律收敛"*）
⇒ **它并不主动消横速**。带 1.1~3.8 m/s 横速 + 5.5~6.0° 残余倾角触地
⇒ 滑移 ⇒ 缓慢倾覆。**这才是倾覆的合理驱动。**

### 3.5 实现

新方法 `fin_control()`（`gfold_land.py`），三轴各一条最简单律：

```
竖直：a_up = a_need - FIN_KD*d(vz)/dt
        a_need = g0 + (vz^2 - vz_tgt^2)/(2h)   <- 在剩余 h 内恰好收到 vz_tgt=-2
水平：a_h  = -FIN_VH_KP*vh_vec - FIN_VH_KD*d(vh_vec)/dt   <- 消横速（补齐缺失环）
姿态：瞄准天顶；倾角 = atan2(a_h, a_up)，夹到 FIN_TILT_MAX_DEG=8°
```

**在 `track()` 之前二选一**（不是之后）—— 否则同帧会双写执行器，
且 `_term_phase` / 锥限幅会与 FIN 打架。

### 3.6 ⚠️ 我在实施中踩到并修掉的两个错（如实记录）

**错误 1：用弱 P 环（第一版）**
```
第一版：a_up = g0 + FIN_KP*(vz_tgt - vz)，再对 a_need 取 min
离线实测落地垂速：-7.25 / -6.87 / -6.18  —— 根本没收到 -2
```
**原因（结构性，调增益解决不了）**：等效增益 = `vz/h`，随 h→0 **无界增长**
（h=5 m 时约 2.1，h=0.5 m 时约 20）。任何**固定**增益都必然在近地时偏小。
**这与本项目此前在 `_term_phase` 上踩过的坑完全同型**
（当时的记录：弱 P 环给 16.5 而物理需要 20.3 ⇒ 落地 −12.2）。
⇒ 改为直接用 `a_need` 作指令（它本身就是增益 = 1/(2h) 的比例律）。

**错误 2：D 项方向反了（反直觉但确凿）**
```
KD=0.00 -> -2.68/-2.66/-3.07/-3.69/-7.43   sum|err|= 9.54   <- 最优
KD=0.05 -> -2.80/-2.76/-3.27/-3.98/-7.51   sum|err|=10.32
KD=0.45 -> -3.70/-3.62/-3.90/-6.35/-10.21  sum|err|=17.79
```
减速过程中 `d(vz)/dt > 0`，叠加 `-KD*d(vz)/dt` 会**减少刹车** ⇒ KD 越大越差。
⇒ `FIN_KD = 0.0`。

**错误 3（自查发现）：倾角固定取满 8°**
第一版「只要 a_h>0 就命令 8°」，于是 a_h 只有 0.1 也无谓支偏 8°，
**落地残余倾角反而变大**。改为 `atan2(a_h, a_up)` 按需比例
⇒ 落地倾角从一律 8.0° 降到 **0.0~2.9°**。

### 3.7 日志新列（142 列）

`fin_on` / `fin_a_up` / `fin_need` / `fin_ah`
（判读：`fin_on=1` 期间 `fin_a_up` 应贴 `fin_need`，且 `vh` 应下降）

### 3.8 ⚠️ 物理边界（别指望它救急）

实测姿态权限有**与油门无关的兵底**（反作用轮）：
`alpha = k*thr + b`，`b` 在 4 趟里恒为正（5.29/5.97/6.75/7.65 deg/s²）。
而 20~40 m 高箭体的**重力倾覆率**约 21~42 deg/s²（per sin(tilt)），远大于该兵底。
⇒ **一旦倾角越过支撑多边形，反作用轮物理上救不回来。**
⇒ FIN 段是**预防性**的（压小落地时的残余横速/倾角），不是「倒了能扶正」。
