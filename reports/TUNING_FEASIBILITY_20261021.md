## 4. 唯一值得调的一个参数：`TILT_CAP_SLOPE`

### 4.1 现状差异

| | 旧程序 | starship |
|---|---|---|
| `TILT_CAP_SLOPE` | **3.0** | **10.0** |
| `cap(alt) = clamp(TILT_CAP_LO + alt/SLOPE, LO, HI)` | | |

低空水平权限对比（`a_up = 10 m/s²`）：

| alt | `cap@10` | `a_h@10` | `cap@3` | `a_h@3` |
|---|---|---|---|---|
| 50 | 10.0° | 1.76 | 16.7° | 2.99 |
| 80 | 13.0° | 2.31 | 26.7° | **5.02** |
| 100 | 15.0° | 2.68 | 33.3° | **6.58** |
| 150 | 20.0° | 3.64 | 35.0° | 7.00 |

**80 m 处 10 度斜率给 2.31 m/s²，3 度斜率给 5.02 m/s² —— 差 2.2 倍。**

### 4.2 但本趟数据显示它不是瓶颈

```
tilt_cmd 达到 cap 的帧: 4/69 = 6%
ah_dem / a_h_max 比值: p50=0.18  p90=0.69  max=1.24
需求超过上限的帧: 2/69 = 3%（都在 78~82 m 高度）
```

**⇒ 改 `TILT_CAP_SLOPE` 最多影响那 6%，而 195348 的 `dist` 误差峰值（4~5 m）不是权限不足造成的。**

### 4.3 结论

**可以试，但预期收益很小（≤1 m）。** 而且它有个真实风险：
`HANDOFF.md §12` 记录了 `slope=10` 是为了「防规划打满 35°」而选的，
改成 3.0 会让规划在 105 m 以上重新打满，**需要重新验证规划倾角闸门**。

## 5. 真正的问题：`vh` 的 6 秒极限环

`195348` 的 `dist` 误差**从不收敛**，在 1.9~5.6 m 之间周期振荡：

| t | `dist` | `vh` | `ah_dem` | `tilt_cmd` |
|---|---|---|---|---|
| 4.56 | 4.56 | 0.67 | 0.61 | 2.46 |
| 7.02 | **2.08** | 0.67 | 0.15 | 0.60 |
| 9.85 | **5.57** | 0.58 | 0.80 | 3.19 |
| 13.12 | **0.68** | 0.41 | — | — |
| 17.26 | **5.02** | 0.34 | — | — |

`vh` 在 0.3~5.9 m/s 之间以 **~6 s 周期**摆。

**这是闭环动力学问题**（方位角旋转 → 切向推力 → 维持公转），
不是任何一个增益或限幅能解决的 —— 见 `HANDOFF.md §10.12` 的四次失败记录。

## 7. 一个我必须承认的发现

`HORIZONTAL_CONTROL_20261010.md` §P4 的建议方向和我的 C 修正**完全相反**：

```python
# 原代码（旧程序与 starship 都有，从未改过）
_az = self.tf_az_dir
if _ah_dem > 1e-9 and _perr > TILT_AZ_MIN_ERR:      # 1.5 m
    _az = (_ah_vec / _ah_dem).copy()
# => |dp| <= 1.5 m 时方位角【冻结】

# P4 的建议（未实施）：解冻
if |dp| > 1.5  OR  angle(_ah_vec, tf_az_dir) > 90deg:
    # 合矢量已掉头 => 冻结值过期 => 也要更新

# 我的 C：再加一层【拒绝】大跳变  <-- 雪上加霜
```

**原代码本来就是「有条件冻结」的。我又加了一层冻结，等于冻上加冻。**

这也解释了 205641 为什么 `az_reject` 高达 84%：

```
195348: perr <= 1.5 的帧 43%（原冻结门已挡住 43%）
        冻结帧里 az_err 单帧跳 > 60 度: 5 次
205641: 我又拒了 84% => 剩下能更新的帧不到 10%
```

**⇒ 如果要动方位角，方向应该是「解冻」（P4），不是「加冻」（我的 C）。**

但 P4 有风险：HORIZONTAL_CONTROL 原文也承认「低空 `|dp|` 抖动，`atan2` 病态」，
建议「同时保留一个方向跳变需连续 N 帧确认的滞环」。**所以它也不是纯调参。**

## 8. 结论

```
问：能不能靠调参解决？

答：不能。
  1. 所有可调增益/限幅通道绑定率 0~8%，调了不生效
  2. 旧程序历史上精度提升 5 倍全靠结构性改动
  3. 旧程序两次调参扫描都被自己否定
  4. 真正的问题是 6 秒极限环（闭环动力学），不是参数

例外：TILT_CAP_SLOPE 是唯一「算参数」的候选，但实测绑定率只 6%，
      预期收益 ≤1 m，且需重验规划倾角闸门。

真正的杠杆：提高交班精度（corr(dist0, distL) = 0.846）。
```
