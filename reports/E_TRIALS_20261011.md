## 2. ★ 最重要的发现：振荡周期**几乎不随增益移动**

这是本轮**决定性的**结果，而且**正好回答了我上轮提出的判据问题**
（"周期是否随参数移动"）。

### 2.1 三种口径交叉验证（避免再犯上轮的周期错误）

```
实验                  瓣×2     FFT    自相关   FFT/时长   瓣数
E1  JERK=1.00        3.59    8.08     n/a      0.50      5
E2a KP=1.0           3.68   12.04    7.64      1.00      5
E2a KP=3.0           3.36   13.15     n/a      1.00      6
E2b KD=2.0           3.34   10.70    7.60      1.00      5
E2b KD=6.0           3.46   11.72    7.15      1.00      5
E3  T=8              3.43    6.01    6.91      0.50      6
基线 KP2/KD4/T6       3.09   11.64    7.33      1.00      6
```

**⚠️ FFT 口径再次被污染**：`FFT主周期/飞行时长 = 1.00`（5 个点）
⇒ **FFT 抓到的是进场趋势，不是振荡**（我上轮踩过同样的坑，
所以这次加了"比值"作为假象指示器，一眼识别）。**FFT 列一律不引用。**

**可用的两个口径**：
```
瓣×2     范围 3.09 ~ 3.68 s   变异系数  5.9%
自相关    范围 6.91 ~ 7.64 s   变异系数  3.8%
```
（自相关给的是瓣×2 的约 2 倍 —— 它抓到的是"完整往复"而非"半周期"，
两个口径**各自内部一致**，结论相同。）

### 2.2 参数改了 3 倍，周期只动 11~17%

```
KP 1.0 → 2.0 → 3.0  （增益 3 倍）:  周期 3.68 → 3.09 → 3.36 s   变化 17%
KD 2.0 → 4.0 → 6.0  （阻尼 3 倍）:  周期 3.34 → 3.09 → 3.46 s   变化 11%
T  6-8 → 8          （外环变化）:  周期 3.09 → 3.43 s          变化 11%

全部 7 点周期范围 3.09~3.68 s，中位 3.39 s，变异系数 5.9%
而同期【阻尼（E 斜率）变化了 6.2 倍】
```

**⇒ 结论（与我上轮的预测一致）：**

> **振荡频率不是姿态环、也不是外环的自然频率** ——
> 它是**由延迟/采样决定的极限环**。
> **增益只能改变"收敛还是发散"（阻尼），不能改变"振多快"（频率）。**

**⇒ 实践含义**：**单靠调增益不可能"消灭"这个振荡，只能把它压成收敛。**
若要改变频率，必须**降低延迟**（当前实测姿态滞后 0.73~0.81 s，见 §4.3）。

### 6.2 若要进一步改（需先做 §6.3 的对照）

#### ★ 延迟预算：瓶颈是**物理帧率**，不是算得慢

```
实验             loop_dt   rpc_ms  ctrl_ms   Py合计   剩余(等帧)  控制率
E1  JERK=1.00     0.2000    6.30    40.70    47.0ms   133.0ms   5.0 Hz
E2a KP=1.0        0.2000    6.30    42.90    49.2ms   130.8ms   5.0 Hz
E2a KP=3.0        0.1800    5.90    41.95    47.9ms   112.2ms   5.6 Hz
E2b KD=2.0        0.2000    6.45    42.10    48.6ms   131.4ms   5.0 Hz
E2b KD=6.0        0.1800    5.80    35.00    40.8ms   119.2ms   5.6 Hz
E3  T=8           0.1800    6.10    39.40    45.5ms   114.5ms   5.6 Hz

Python 侧（rpc+ctrl）只占一帧的 ~25%，其余是"等下一个物理帧"
姿态滞后 0.73~0.81 s = 3.6~4.0 个控制帧
```

**⇒ Python 每帧只花 ~47 ms，却要等 ~130 ms 才到下一帧。**
**⇒ 延迟的根源是【控制循环每物理帧只跑一次】，而不是计算慢。**

**这意味着**：
- **"关掉 `--debug-lines`"没用** —— `ctrl_ms` 里包含控制计算，
  而画线（`seg_draw`）根本**没进 `COLS`**，且从 `ctrl_ms` 的分布看不是大头。
- **真正能改频率的杠杆是提高物理帧率**：
  KSP 设置里的 **"Max Physics Delta-Time per Frame"**（最大物理步长）。
  `loop_dt ≈ 0.18~0.20 s` 说明**每个物理步覆盖 0.2 s 游戏时间（= 5 Hz）**，
  这远低于 KSP 默认（0.02~0.04 s = 25~50 Hz）。
  **把该设置调小（例如 0.04）⇒ 控制率提到 25 Hz ⇒ 滞后从 4 帧降到 <1 帧。**
  **代价**：游戏实时速度变慢（同样一段飞行要更多真实时间），
  且对 CPU 要求更高。**这是唯一能改变振荡【频率】的手段。**
- **`--dt` 默认 0.02 s 不是瓶颈**（它只是 sleep 上限，实际被物理帧率主导）。

2. **`E3 T=8` 是单一最好的一趟，但只有 1 个样本**，可能含运气成分
   （它的入场 `vh0`=6.9 也略优于基线 6.5）。**建议复飞确认。**
3. **`E1`（P1 开关）的对比不干净**：入场 `vh0`/`dist0` 有差异，
   **我不能据此判断 P1 的净效果**，故 §6.3 要求补一次对照。
4. **FFT 口径再次被证明不可用**（`周期/时长`=1.00），**本轮只引用
   瓣×2 与自相关两个口径**；两者各自内部一致，但**绝对周期值仍有口径歧义**
   （自相关约是瓣×2 的两倍），**我只用"是否随参数移动"这个相对结论**。
5. **姿态滞后测量只有 4~7 个有效窗**，是量级估计，不宜当精确值。
6. **`post_sas` 全 0 是设计使然**，不是功能失败；SAS 生效是**由录像目视确认**的
   （RCS 灯亮 + SAS 灯亮 + navball 径向标记），**不是由日志确认的**。
7. **我没有做闭环仿真**；以上全部来自真飞日志与录像。
